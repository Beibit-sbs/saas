## 3. B1 Blocker Source

The B1 blocker came from `tests/test_postgres_persistence_xv2.py`.

The exact failing tests were:
- `TestPostgresMigrations::test_alembic_version_table_exists`

- `TestPostgresTransactionIsolation::test_uncommitted_not_visible`

The failure signature was a `RuntimeError` from `app/core/db.py` complaining that `DATABASE_URL` was not set.

## 4. Failure Classification

The blocker is classified as a test-fixture isolation issue rather than a product regression.

Why:
- `backend/tests/conftest.py` intentionally removes `DATABASE_URL` during test setup/teardown so most test slices run in-memory.
- `tests/test_postgres_persistence_xv2.py` was the outlier because it called `build_engine()` directly without restoring the captured DB URL first.
- the compose container itself does provide a live `DATABASE_URL`, so the failure was caused by test-process environment cleanup, not by missing compose configuration.

## 5. Root Cause Analysis

The module-scoped `pg_engine()` fixture in `tests/test_postgres_persistence_xv2.py` created a direct SQLAlchemy engine from `build_engine()`.

Because the backend test harness deliberately pops `DATABASE_URL` in `conftest.py`, the fixture saw an empty environment and raised before any migration or CRUD assertions could run.

That means the failing behavior was:
- deterministic
- local to the integration test slice
- fixable without changing application runtime code

## 6. Remediation Strategy Selected

Selected strategy:
- capture `DATABASE_URL` at module import time
- restore it inside the module-scoped fixture immediately before `build_engine()`
- skip the module if no live DB URL is available at import time

This preserves the suite’s normal in-memory isolation while allowing the explicit PostgreSQL persistence test to opt into the live DB path.
