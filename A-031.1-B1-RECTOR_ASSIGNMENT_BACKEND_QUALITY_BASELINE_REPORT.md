## 16. Performance Diagnosis

### Classification
- PRIMARY: LIVE_DB_SETUP_OVERHEAD
- SECONDARY: TESTCLIENT_APP_SETUP_OVERHEAD (collection time)

### Root Cause

**Primary cause** — Global conftest `reset_shared_state` autouse fixture (conftest.py line 238):
- This fixture is session-scoped autouse, running for every test in the entire project
- Implementation: calls `_reset_template_state()` TWICE per test (once before yield, once after)
- `_reset_template_state()` does:
  1. `os.environ.pop("DATABASE_URL", None)` — removes env var
  2. `clear_shared_engine()` — disposes SQLAlchemy engine pool
  3. `with UnitOfWork() as uow:` — opens new DB connection
  4. 10× `uow.xxx_repository.clear_state(conn=uow.conn)` — resets all shared repository state tables
- Cost per call: ~7-8s (live DB connection + 10 table resets)
- Cost per test: ~7-8s × 2 = ~15s
- Evidence: 167 tests × 15s = ~2505s observed ≈ 2760s actual (consistent with overhead model + collection time)

**Secondary cause** — Module-level `_auth_headers()` calls in api/security/audit test files:
- Each `_auth_headers()` call invokes `resolve_permissions_for_tenant()` (live DB call) at module import/collection time
- api file: ~30s (VIEWER_HEADERS)
- security file: ~60s (VIEWER_HEADERS + STUDENT_HEADERS)
- audit file: ~34s (ADMIN_HEADERS from conftest import)
- Domain file: 0.06s (no module-level auth calls)
- Total collection overhead: ~124s of 2760s

### Performance Comparison

| Test Category | Tests | Duration | Per-Test | Pattern |
|---|---|---|---|---|
| A-031.1 combined | 167 | 2760s | ~16.5s | LIVE_DB_SETUP_OVERHEAD |
| A-030 continuity (PYTHONPATH mount) | 958 | 0.75s | ~0.0008s | PURE_INTROSPECTION (no DB) |

The difference confirms: A-031.1 domain/api/security/audit tests exercise real TestClient + DB reset cycle; A-030 foundation tests are pure Python introspection without DB interaction.

### Remediation Assessment

**NOT SAFE TO REMEDIATE IN A-031.1-B1 SCOPE:**
- `reset_shared_state` is a global autouse fixture in the root conftest.py
- Modifying it would affect ALL 1671+ tests in the project
- Risk of breaking other passing tests is HIGH
- Correct remediation path: scoped performance optimization sprint (e.g., A-031.1.B2-PERFORMANCE) with full regression gate before merge

**Classification decision**: ACCEPTABLE_DB_INTEGRATION_COST / PRE_EXISTING_INFRASTRUCTURE_PATTERN

The per-test overhead is consistent with all other API/security/audit test files in this project. A-031.1 tests do not introduce a NEW performance regression.

## 23. Performance Note (Follow-Up Recommendation)

**Status**: PERFORMANCE_NOTE_ONLY — does not block B1 closure

The 16.5s/test overhead is a project-wide infrastructure characteristic. It affects all test suites equally. If the test harness performance becomes a bottleneck, the recommended path is:

1. Isolate `reset_shared_state` to suites that require it (requires careful per-suite analysis)
2. Use `@pytest.mark.usefixtures` opt-in rather than global autouse
3. Replace `UnitOfWork()` resets with targeted mock-based isolation for unit tests
4. Run in separate CI lanes with parallelism

This work should be scoped as a dedicated performance sprint (e.g., A-031.1.B2-PERFORMANCE) to avoid destabilizing the existing 1671+ test baseline.
