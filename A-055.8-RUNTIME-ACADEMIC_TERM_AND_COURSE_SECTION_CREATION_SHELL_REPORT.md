# A-055.8 Runtime Academic Term And Course Section Creation Shell Report

Date: 2026-06-18

## Scope

Eighth correction slice after scheduling section selector:

```text
tenant admin
  -> create/select academic term
  -> create course section from course + term
  -> enroll student into section
```

The goal of this slice was to remove the remaining manual database setup gap before enrollment.

## Backend Result

Enrollments now exposes tenant-scoped academic term APIs:

```text
POST /api/admin/academic-terms
GET  /api/admin/academic-terms
```

Create payload:

```text
term_code
term_name
start_date
end_date
add_drop_deadline
status
metadata_json
```

List supports:

```text
page
page_size
status
```

These terms are the same canonical records used by scheduling sections and enrollment validation.

## Frontend Result

Scheduling page now includes an academic setup flow:

```text
create academic term
  -> select course
  -> select term
  -> create course section
```

Course section creation now sends the backend-shaped payload:

```text
course_id
term_id
section_code
instructor_id
max_capacity
```

This closes the practical setup chain needed before enrollment:

```text
Program
  -> Course
    -> Academic Term
      -> Course Section
        -> Enrollment
```

## Test Coverage Added

`SchedulingPage.test.tsx` now verifies:

- academic term and section setup panel renders
- course selector is populated from courses
- term selector is populated from academic terms

## Current Limits

Course section creation is now possible, but lesson instance creation is still not ergonomic in the UI. Attendance still starts from manual lesson instance id input.

The next clean slice should connect:

```text
section
  -> lesson instance
  -> attendance
```
