### 1. UCE-004 — Leave Management

**Current State:** L3 deterministic leave type → approval state → record tracking logic

**Proposed L4 Service Summary:**
- Function: `get_leave_management_l4_visibility_summary(tenant_id: int) → dict`
- Module: `backend/app/modules/leave_management/service.py`
- Service location: New function in existing service.py

**L4 Visibility Surface:**
- Leave application status (pending, approved, rejected, completed)
- Approval workflow stage
- Deadline and expiration tracking
- Human-review gates (pending manager review, HR review)
- Aggregate approval times and blockers
- No leave record mutation
- No approval workflow execution

**Tenant Safety:**
- `tenant_scoped: true` — All data filtered by tenant_id
- Fail-closed if tenant_id invalid (403)
- No cross-tenant data leak possible

**Read-Only Evidence Source:**
- Reads leave requests table (filtered by tenant)
- Reads approval audit log (existing L3)
- No writes allowed at L4

**Output Fields:**
- `readiness_summary`: Leave approval pipeline readiness
- `risk_summary`: Blocked approvals, missing evidence, overdue items
- `evidence_summary`: Required approval chains, present signatures, missing sign-offs
