## 5. Backend Module Strategy

### Decision: Single Productized Module

**Module path**: `backend/app/modules/document_workflow_os/`

**Rationale**:
- The L2 envelope modules (`document_workflow`, `order_decree_registry`, `incoming_outgoing_correspondence`) each contain only `service.py` with no DB, no models, no routes
- Productization creates a new integrated vertical module rather than fragmenting into 3+ separate model/route files
- Mirrors the A-031 pattern: `rector_assignment_workflow` consolidates all assignment domain entities under one module
- Follows `_os` naming convention for OS-level productized verticals

**Module file structure** (to be created in A-032.1-RUNTIME):

```
backend/app/modules/document_workflow_os/
├── __init__.py
├── dependencies.py        # DB session dependency (pattern: get_doc_workflow_db)
├── models.py              # SQLAlchemy ORM models (14 tables, prefix: doc_)
├── permissions.py         # Permission constants (28 permissions)
├── repository.py          # DB query helpers (40 methods)
├── schemas.py             # Pydantic schemas (35 total)
├── service.py             # Business logic (18 functions)
└── router.py              # FastAPI router (33 routes)
```

### Table Prefix Convention

- `doc_documents`

The existing L2 modules (`document_workflow`, `order_decree_registry`, `incoming_outgoing_correspondence`) are **not modified** in A-032.1. They remain as L2 foundation contracts. The new `document_workflow_os` module is the productized implementation that subsumes their scope.

## 11. Service Contract

Following A-031 service pattern:
- Functions accept `db: Session, tenant_id: int, actor_user_id: int, ...`
- Call `validate_tenant_id_provided(tenant_id)` first
- Call `repo_require_*` for entity existence
- Validate status transitions (raise `DomainValidationError` on invalid)
- Write status history via `repo_add_status_history`
- Write audit event via `repo_add_audit_event`
- Write to `log_admin_action` (from `app.modules.audit.service`)
- No external calls
- No auto-signature
- No hard delete

## 15. Rector Assignment OS Integration Contract

### Design Principles
1. **Human-initiated only**: No automatic assignment creation from document/decree/correspondence transitions
2. **Tenant-scoped validation**: Assignment must belong to same tenant
3. **Audit both sides**: Document side creates audit event (assignment side does not need to be mutated)
4. **No circular state sync**: Document status and assignment status evolve independently
5. **Cross-module reference by ID**: FK constraint NOT CREATED (cross-module links use BigInteger field without SQLAlchemy FK declaration to avoid cross-module migration coupling; integrity enforced at service layer)

### Integration Points

**Document → Assignment link** (via `doc_document_assignment_links`):
```
POST /api/admin/documents/{document_id}/link-assignment/{assignment_id}
  service: link_document_to_assignment()
  validates: document exists in tenant (repo_require_document)
  validates: assignment_id is a valid integer (type check only in A-032.1; cross-module lookup deferred)
  creates: DocDocumentAssignmentLink row
  audit: ASSIGNMENT_LINKED event on document side
  link_types: SOURCE_DOCUMENT, EXECUTION_DOCUMENT, EVIDENCE
```

**Resolution → Assignment link** (via `doc_resolution_assignment_links`):
```
POST /api/admin/documents/resolutions/{resolution_id}/link-assignment/{assignment_id}
  service: link_resolution_to_assignment()
  validates: resolution exists in tenant
  creates: DocResolutionAssignmentLink row
  audit: RESOLUTION_ASSIGNMENT_LINKED event
```

**No Mutations to A-031 Tables**: A-032.1 does not modify any `rector_assignment_*` tables. Linkage is recorded only in `doc_document_assignment_links` and `doc_resolution_assignment_links`.

**Future Extension (A-032.x)**: When A-032 assignment-doc bi-directional audit is needed, a dedicated integration event service will be added that notifies A-031 side via a shared audit utility (not in A-032.1 scope).

## 16. Dashboard Contract

### Computation Specification

`repo_compute_dashboard_summary(db: Session, tenant_id: int) -> dict`

{
    "total_documents": SELECT COUNT(*) FROM doc_documents WHERE tenant_id=:tid AND archived_at IS NULL,
    "registered_documents": COUNT WHERE status IN ('REGISTERED','UNDER_REVIEW','APPROVED','SIGNED','ISSUED',...),

    "returned_for_revision_count": COUNT WHERE status = 'RETURNED_FOR_REVISION',
    "approved_count": COUNT WHERE status = 'APPROVED',
    "signed_count": COUNT WHERE status = 'SIGNED',
    "archived_count": COUNT WHERE archived_at IS NOT NULL,
    "incoming_correspondence_count": SELECT COUNT FROM doc_correspondence_items WHERE direction='INCOMING' AND archived_at IS NULL,
    "outgoing_correspondence_count": SELECT COUNT FROM doc_correspondence_items WHERE direction='OUTGOING' AND archived_at IS NULL,
    "overdue_document_reviews": COUNT WHERE status='UNDER_REVIEW' AND created_at < NOW() - INTERVAL '7 days',
    "documents_linked_to_assignments": SELECT COUNT(DISTINCT document_id) FROM doc_document_assignment_links WHERE tenant_id=:tid,
    "decrees_pending_signature": SELECT COUNT FROM doc_order_decrees WHERE status='APPROVED_FOR_SIGNING' AND archived_at IS NULL,

## 17. Security / Tenant / Audit Contract

### Tenant Isolation (Mandatory)
- Every entity has `tenant_id: BigInteger NOT NULL index`
- Every repository query: `where(Model.tenant_id == tenant_id, ...)`
- Body `tenant_id` field ignored (sourced from `get_current_tenant` JWT dependency)
- `validate_tenant_id_provided(tenant_id)` called at every service function entry
- Cross-tenant IDs raise `TenantResourceNotFoundError`
- No global list queries across tenants

### Audit Requirements (Mandatory)
- `repo_add_audit_event` called after every mutation:
  - entity_type: "document" | "decree" | "correspondence" | "resolution"
  - entity_id: the entity PK
  - event_type: AuditEventType constant
  - actor_user_id: from auth context
  - action: human-readable description
  - payload_json: previous_status, new_status, request_id, key metadata
- `repo_add_status_history` called for every status transition
- `doc_audit_events` is append-only; no update/delete of audit rows
- All audit writes inside the same DB transaction as the entity mutation

### Archive / No Hard Delete
- Soft archive: set `status=ARCHIVED` + `archived_at=now()` + create `doc_archive_records` row
- No `DELETE FROM` statements anywhere in the module
- No cascade hard delete
- `CANCELLED` state for intentional abandonment (not deletion)

### Registry Number Integrity
- `registry_number` assigned at registration step only (single service call)
- After assignment, `registry_number` field is immutable
- Update attempts to `registry_number` on registered entities raise `DomainValidationError`
- Correction workflow: creates a new `doc_decree_registry_entries` row with `correction_of_entry_id` reference (deferred feature; tracked in A-032.x)
- `UniqueConstraint` enforced at DB level per tenant

### API Error Responses
Following A-031 router helpers:
- `TenantResourceNotFoundError` → 404
- `DomainValidationError` → 400
- `OptimisticLockConflictError` → 409
- FastAPI `IntegrityError` → 409 via `integrity_error_to_http`
- Missing permission → 403
