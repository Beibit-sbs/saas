## 4) Part C - Selected Wave 3 Top 5

### 4.1 Feature 1: Budget Overrun Prevention Brain
- Why selected:
  - Highest strategic value for finance autonomy and direct executive control impact.
  - Strong fit for signal -> decision -> action -> outcome -> KPI loop.
- Modules involved:
  - budget, finance, procurement, brain_core, platform.kpi, platform.event_ingestion.
- Existing code to reuse:
  - brain_core signal classification/planning/dispatch patterns from Wave 1/2.
  - KPI lineage and threshold patterns in backend/app/platform/kpi/service.py.
- Likely missing links:
  - Budget baseline and commitment signals, budget-cycle context binding.
- Brain Core role:
  - Detect overrun risk, choose mitigation policy, trigger approvals/interventions.
- KPI/output:
  - budget_overrun_risk_open, prevented_overrun_count, mitigation_lead_time.
- Risk:
  - Medium due to policy calibration and false-positive control.

### 4.2 Feature 2: Procurement Request -> Approval -> PO Automation
- Why selected:
  - Core autonomy workflow with clear operational throughput and delay reduction.
- Modules involved:
  - procurement, approvals, finance, brain_core, jobs.scheduler, platform.events.
- Existing code to reuse:
  - decision approval flow, dispatch bridge, scheduler orchestration, audit trail patterns.
- Likely missing links:
  - Procurement state machine harmonization and approval policy profiles.
- Brain Core role:
  - Prioritize requests, route to approvers, escalate blocked approvals.
- KPI/output:
  - request_to_approval_time, approval_sla_breach_count, auto_routed_ratio.
- Risk:
  - Medium due to policy/exception handling breadth.

### 4.3 Feature 3: Purchase Order -> Delivery -> Asset Inventory Chain
- Why selected:
  - Strongest procurement-to-asset closed loop; high integration and audit value.
- Modules involved:
  - procurement, receiving, inventory/assets, finance, event_ingestion, kpi.
- Existing code to reuse:
  - event ingestion contract model, tenant-safe KPI aggregation, cross-feature E2E structure.
- Likely missing links:
  - PO-delivery-asset linkage IDs and reconciliation checkpoints.
- Brain Core role:
  - Detect stalled handoffs and trigger follow-up/escalation actions.
- KPI/output:
  - po_delivery_gap_rate, asset_registration_latency, chain_completion_rate.
- Risk:
  - Medium due to multi-step data consistency requirements.

### 4.4 Feature 4: Finance Operations Health Dashboard
- Why selected:
  - Fastest high-visibility value for rector/admin dashboards using existing frontend/KPI infrastructure.
- Modules involved:
  - platform.kpi, admin console frontend pages/components, finance metric providers.
- Existing code to reuse:
  - Wave 2 KPI frontend wiring pattern and reusable KPI bar components.
  - Existing dashboard routing and tenant-bound metrics API.
- Likely missing links:
  - Domain-specific finance widgets and alert thresholds.
- Brain Core role:
  - Explainability and recommendations panel for operational anomalies.
- KPI/output:
  - finance_ops_health_score, unresolved_finance_alerts, action_closure_rate.
- Risk:
  - Low-to-medium; mostly composition and threshold tuning.

### 4.5 Feature 5: Inventory Low Stock / Supply Risk Brain
- Why selected:
  - Directly supports autonomous operations continuity and asset readiness.
- Modules involved:
  - inventory, supply/procurement, brain_core, scheduler, kpi.
- Existing code to reuse:
  - risk classifier templates, planner action mapping, intervention/escalation semantics.
- Likely missing links:
  - Reorder policy encoding and supplier lead-time signal ingestion.
- Brain Core role:
  - Predict stock-out risk and trigger replenishment/escalation decisions.
- KPI/output:
  - low_stock_risk_open, prevented_stockouts, replenishment_cycle_time.
- Risk:
  - Medium; depends on signal quality and lead-time assumptions.
