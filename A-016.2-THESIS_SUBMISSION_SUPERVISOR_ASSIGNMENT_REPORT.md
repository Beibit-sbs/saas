## Severity Model

| Severity | Reasoning Path | Conditions |
|----------|---------------|------------|
| CRITICAL | `thesis_governance_critical` | `risk_level=="critical"` OR no supervisor ≥30 days OR `days_in_review ≥ 90` |
| HIGH | `thesis_governance_high` | `risk_level=="high"` OR no supervisor ≥14 days OR thesis rejected OR supervisor overloaded OR `days_in_review ≥ 60` |
| MEDIUM | `thesis_governance_medium` | `risk_level=="medium"` OR no supervisor (no day info) OR `days_in_review ≥ 30` OR `supervisor_load_pct ≥ 80` |
| LOW | `thesis_governance_low` | Default case |

## Security Properties

### Fail-Closed Validation
- `tenant_id ≤ 0` → returns `status: "rejected"` with reason `"missing_tenant_context"`
- `thesis_id` empty/missing → returns `status: "rejected"` with reason `"missing_thesis_id"`
- Missing optional fields (`supervisor_id`, `student_id`) → signal processed with evidence metadata attached

### No Automatic Punitive Action
- No actions in any severity tier include automatic discipline, suspension, or score modification
- CRITICAL decisions include `requires_approval=True` — a human must sign off before any action is executed
- All supervisor assignment decisions route to human academic office review

### Cross-Tenant Isolation
- `list_decisions(tenant_id=N)` returns only decisions for that tenant
- Verified via test: tenant 1 and tenant 2 decision objects are disjoint in memory

### Deduplication
- Identical signal (same tenant + same event payload) submitted twice → second call is deduplicated and returns `status: "deduplicated"`
