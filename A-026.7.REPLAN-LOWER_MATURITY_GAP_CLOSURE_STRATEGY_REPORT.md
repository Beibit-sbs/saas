## 10. L2 Foundation Contract Standard

### Definition of L2 (Service Contract Foundation)

Each selected L1→L2 module must deliver:

#### 1. Service Function Skeleton
- `service.py` with deterministic functions
- Input validation + tenant guard (fail-closed)
- Output dict/schema with deterministic fields
- Status constants where applicable
- Allowed/forbidden action lists where applicable
- No DB mutations
- No external API calls
- No KPI computation
- No Brain execution
- No autonomous actions

#### 2. Contract Output Structure
```python
{
  "tenant_id": <int>,
  "module": <string>,
  "readiness_level": "L2",
  "status": <deterministic_status>,
  "classification": <deterministic_classification>,
  "allowed_actions": [<actions>],
  "forbidden_actions": [<actions>],
  "safety_flags": {
    "tenant_scoped": true,
    "fail_closed": true,
    "no_fake_data": true,
    "no_autonomous_execution": true,
    "no_l3_claim": true
  },
  "evidence_notes": <deterministic_rationale>
}
```

#### 3. Tenant Safety (Mandatory)
- `validate_tenant_id(tenant_id)` function
- Reject None, 0, -1, invalid tenant_id → ValueError
- All output scoped to tenant_id
- No cross-tenant aggregation
- No default tenant fallback

#### 4. Tests (20-40 per module expected)
- Import validation
- Tenant fail-closed validation
- Service function determinism
- Status/classification logic
- Allowed/forbidden action protection
- Anti-inflation validation

#### 5. Anti-Inflation Boundaries
- ✓ No API endpoint
- ✓ No frontend page
- ✓ No DB mutation
- ✓ No KPI values
- ✓ No Brain signal
- ✓ No event emission
- ✓ No autonomous execution
- ✓ No L3/L4/L5/L6 claim
