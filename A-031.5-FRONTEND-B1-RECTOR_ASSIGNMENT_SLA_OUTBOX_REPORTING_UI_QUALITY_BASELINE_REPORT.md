## 18. Known Limitations

1. **No backend SLA/outbox/escalation-policy routes implemented yet**: The frontend hooks call `/api/admin/rector-assignments/outbox`, `/sla-policies`, `/escalation-policies` but these are not yet implemented in the backend. Calls will return 404 at runtime. This is by design — frontend-first spec for future backend implementation.

2. **No live notification dispatch**: The outbox UI shows intent records only. No email/SMS provider is connected. This is an explicit design constraint stated in all required labels.

3. **Manual confirmation for escalation only**: Escalation policies with `require_manual_confirmation=true` (hardcoded default) require human review — no autonomous dispatch exists.

4. **Analytics fields may be absent**: All 6 dashboard widgets show "unavailable" state gracefully when backend does not return analytics fields. No fallback to zero.

5. **E2E not yet validated**: A-031.5-E2E will cover full end-to-end validation when backend routes are implemented.

6. **`api_bff_scan.log` contains SLA policy `apiPatch` path**: `apiPatch` for SLA update uses standard BFF path — no issue, matches existing pattern.
