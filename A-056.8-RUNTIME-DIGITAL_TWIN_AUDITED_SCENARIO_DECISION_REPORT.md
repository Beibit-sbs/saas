# A-056.8 Runtime - Digital Twin Audited Scenario Decision Report

## Scope

Close the NATIONAL_OS_TREE #21 loop — "Human approves. Audit records." — by
letting a reviewer record a decision on a what-if scenario, written to the real
audit trail, executing nothing.

## Design choice (no new table / migration)

A decision IS an audit record, so it is written via the existing audit module
(`audit.service.log_admin_action` → `app_audit_events`, DB + in-memory fallback)
rather than a new `digital_twin_decisions` table. This avoids a risky
EntityConfig/migration change to shared university_core, and is more correct: the
decision lands in the canonical audit trail with a correlation_id.

## Result

- Backend route: `POST /api/admin/digital-twin/scenarios/decision`
  (new `digital_twin.decision.record` permission; route count 5→6, permission 3→4 module-local).
- Request: `{ scenario_name, decision ∈ accepted|rejected|deferred (regex-validated),
  rationale, intake_growth_percent? }`.
- Service `record_scenario_decision`: tenant fail-closed + actor-bound; emits an
  audit event `digital_twin.scenario_decision_recorded` with the decision metadata
  and `no_autonomous_execution=true`; returns the correlation_id + echoed decision.
- The twin records that a human decided; it executes NOTHING.
- Frontend: read-only "Human decision → audit" section on /console/digital-twin.

## Safety / Honesty

- `no_autonomous_execution=true`, `human_review_required=true`, `fake_metrics=false`.
- Invalid decision values are rejected (422). Viewer without the permission denied (403).
- The decision is auditable end-to-end (actor → action → correlation_id → app_audit_events).
