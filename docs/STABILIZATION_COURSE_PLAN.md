# Stabilization Course Plan

## Главная цель
Закрыть уязвимости и операционные риски до активной разработки новых фич.

## Жесткие правила курса
1. Никаких широких изменений сразу в backend + frontend + infra в одном пакете.
2. Каждый шаг должен иметь проверку и критерий "готово/не готово".
3. Любой рискованный шаг сначала в dry-run или с планом отката.
4. Любая новая фича только после прохождения security + stability гейтов.

## Этапы Roadmap

### Этап A: Секреты и репо-гигиена
Фокус: убрать секреты из tracked-файлов и закрыть ignore-политику.

Definition of Done:
- Нет секретов в tracked-файлах.
- В .gitignore есть правила для локальных токенов/сертов.
- Выполнена проверка поиска секретов по репозиторию.

### Этап B: Auth/доступы и fail-closed поведение
Фокус: явные permission checks и отказ по умолчанию при ошибках зависимостей.

Definition of Done:
- Внутренние маршруты имеют явные permission checks.
- Убраны небезопасные дефолтные пароли/секреты.
- Все чувствительные проверки fail-closed.

### Этап C: Надежность пайплайна и безопасные скрипты
Фокус: предсказуемый pipeline без разрушительных действий по умолчанию.

Definition of Done:
- Pipeline не удаляет данные по умолчанию.
- Все рискованные операции выделены в explicit-режим.
- Скрипты имеют понятные preflight-проверки.

### Этап D: Release discipline и контроль качества
Фокус: обязательные гейты и воспроизводимый rollback.

Definition of Done:
- Каждый merge проходит обязательные security/stability гейты.
- Есть рабочая rollback-процедура и проверка восстановления.
- Есть единый релизный чеклист.

## Формат ежедневного ведения
- Статус: что закрыто сегодня.
- Смысл: что это дает по рискам.
- Честный вывод: где остались дыры.
- Следующий шаг: один конкретный шаг на сегодня.

## Антисрыв курса
Если начинается хаос:
1. Стоп новых фич.
2. Возврат к текущему этапу.
3. Закрытие 1 критичного риска до любых новых задач.
4. Повторная валидация гейтов.

## Текущий фокус
- Активный этап: A (Секреты и репо-гигиена)
- Критичный риск дня: секреты в tracked-файлах
