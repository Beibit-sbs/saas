# A-015.2 - Procurement Request -> Approval -> PO Automation

Date: 2026-05-05
Action ID: A-015.2
Status: CLOSED - PASS
Predecessor: A-015.1

## Scope

Implement additive-only procurement approval automation across Brain Core and procurement service so that:

1. `procurement.request_submitted` and `procurement.approval_required` are accepted by Brain Core.
2. High and medium risk procurement requests create approval workflow actions.
3. Low-risk requests remain non-actionable.
4. Signals fail closed when procurement request context is missing.
5. Procurement submission / approval / PO issuance flows emit canonical events.
6. Approval transition and PO creation helpers are idempotent.
7. Tenant isolation and signal dedup remain intact.

All changes are additive. No migrations or public endpoint removals were introduced.

## Delivery Summary

### Brain Core Routing

- `procurement.request_submitted` and `procurement.approval_required` now route to `procurement_approval_automation`.
- Risk classification is threshold-based:
  - high: `estimated_total >= 50000` or `priority in {high, critical}`
  - medium: `estimated_total >= 10000` or `priority == medium`
  - low: below those thresholds
- High risk dispatches:
  - `create_procurement_approval_case`
  - `notify_procurement_team`
- Medium risk dispatches:
  - `create_procurement_approval_case`
- Low risk dispatches no workflow action.

### Signal Normalization and Safety

- `_normalize_procurement_approval_signal()` rejects events that have neither `request_id` nor `estimated_total`.
- The normalizer enriches payloads with:
  - `procurement_risk_origin`
  - `procurement_risk_evidence`
  - canonical `source_module`, `source_entity_type`, `source_entity_id`
- Existing dedup behavior remains tenant-scoped and event-scoped.

### Procurement Lifecycle Wiring

- `submit_procurement_request()` emits `procurement.request_submitted`.
- `update_procurement_status()` emits `procurement.approved` / `procurement.rejected` when those transitions occur.
- `create_procurement_order()` emits `procurement.po_issued`.
- `ensure_procurement_approval_action()` idempotently moves a submitted request to `under_review` and returns approval steps.
- `ensure_po_on_approved_request()` idempotently creates or reuses a PO for approved requests and returns `None` for non-approved requests.
