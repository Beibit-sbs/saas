# A-022.5 Timetable Change KPI / Dashboard Report

## Summary
A-022.5 adds a read-only KPI/dashboard surface for the human-approved timetable workflow. The implementation is additive-only, tenant-scoped, and intentionally non-destructive.

## What Was Added
- Backend KPI titles and deterministic event lineage in `backend/app/platform/kpi/service.py`
- Valid timetable workflow events in `backend/app/platform/events/registry.py`
- Matching ingestion allow-list entries in `backend/app/platform/event_ingestion/types.py`
- A read-only rector dashboard KPI section in `frontend/app/(admin)/console/dashboard/page.tsx`
- Contract coverage in `frontend/__tests__/admin/RectorDashboardPage.test.tsx`
- Backend KPI contract suite in `backend/tests/platform/test_platform_kpi_timetable_workflow_a0225.py`

## KPI Coverage
The dashboard now exposes event-derived counters for:
- timetable proposals
- pending review proposals
- approved / declined proposals
- revision requests
- simulations
- simulation review-required signals
- simulation conflict created/resolved counts
- approval queue and approval status counts
- high-risk approval cases

## Safety Properties
- No timetable mutation
- No room reservation
- No booking override
- No auto-apply
- No cross-tenant leakage
- Missing events default to zero
- Labels stay policy-safe and read-only

## Policy-Safe Labeling Note
During validation, the title `Rejected` tripped a destructive-word policy scan via substring matching. The final surface uses `Declined` where needed to keep the dashboard compliant with non-destructive wording requirements.
