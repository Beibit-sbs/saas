# A-056.G1 — Test-Collection Integrity: 11 Uncollectable Test Files

## Why this matters

A test file that fails to **collect** (import error) never runs — pytest reports it as
an ERROR, but a `pytest <subset>` or CI run scoped elsewhere shows green. This is the
ultimate false-green: invisible, zero-signal coverage that *looks* fine. A full-tree
`pytest tests/` is interrupted by these, and any selective run silently omits them.

A collection sweep (`pytest tests/ --collect-only`) found **11 uncollectable files**
(`18392 tests collected, 11 errors`). Two distinct root causes; cause B further split
once the files were actually run.

## Cause A — removed `communications.create_message` API (5 files) — DECISION NEEDED

Files (all import `app.modules.communications.service` (singular), which no longer exists):
- tests/modules/communications/test_communications.py
- tests/modules/communications/test_service_hardening_cxiv.py (`create_message`, `_metric`, `_record_outcome`)
- tests/test_week37_domain_depth.py (`create_message`, `_ACTIVE_MESSAGE_STATUSES`, `_LARGE_AUDIENCE_THRESHOLD`, `_MESSAGE_TYPE_MAX_ACTIVE`)
- tests/test_week117_domain_depth.py
- tests/test_week151_domain_depth.py

Root cause (evidence, not a rename): commit **db2e00f2** (wave45 A-054.5-E1) **deleted**
`communications/service.py` (−288 lines) and added `communications/services.py` (+117 lines)
— a deliberate replacement of the old in-DB **message-sending** service with a
**metadata-only runtime shell + registries**. Verified the old capability was **dropped,
not relocated**: `def create_message` and the message-cap/threshold constants exist
**nowhere** in `app/` anymore. So the 5 tests assert against deleted code.

**Operator decision (surfaced, not auto-resolved):**
1. **Quarantine/remove the 5 obsolete tests** — they test deleted pre-wave45 functionality;
   Communications is intentionally metadata-only now. *Recommended.*
2. **Restore the message-sending capability** — if outbound messaging (caps/throttle) is still
   required and wave45 dropped it prematurely, the tests are a signal to re-introduce it.

Not executed unilaterally because it ratifies a capability removal.

## Cause B — wrong `backend.` import prefix (6 files)

Root cause: `from backend.app.modules.X.service import …` — a `backend.` package prefix not
importable in the canonical harness (pytest rootdir = `backend/`, top package = `app`). The
referenced `.service` modules all exist, so the import path is simply wrong. Fix: `backend.app`
→ `app`. But on actually RUNNING them, the 6 split:

### B1 — fixed + verified (2 files) — DONE
- tests/test_a0303_sensitive_domain_readiness_foundation.py → **189 passed (0.26s)**
- tests/test_a0304_disciplinary_sensitive_readiness_foundation.py → **93 passed (0.18s)**

Pure deterministic-logic tests, no infra. Import fix applied and committed. **+282 tests
restored** to the runnable suite (were 0).

### B2 — import fix correct BUT hangs host-side (4 files) — REVERTED, flagged
- tests/test_a02813_expansion_l4_visibility_batch4.py
- tests/test_a0286_expansion_l4_visibility_batch2.py
- tests/test_a0293_provider_readiness_foundation_batch2.py
- tests/test_a0295_provider_readiness_l3_deterministic_logic.py

With the import fixed these COLLECT, but running them **hangs** (confirmed: a0293 exit 124
after ~3 tests pass; a combined run sat at 0.4% CPU for 53 min). The hang is mid-run (a
specific test/fixture blocks — likely a real DB/infra dependency not present in the host
probe; the canonical path is the docker `backend-tests` service with `db` up).

**Disposition:** the sed fix on these 4 was **reverted** to their original `backend.`-prefix
state. Rationale: a *collection error* is non-blocking (pytest reports it and continues),
whereas a *hang* blocks the entire suite — shipping a hang into the default `pytest tests/`
would be strictly worse. The import-path bug is real and the fix is ready, but these need to
be run/validated in the canonical docker harness (with DB) before the fix is shipped, and the
hanging test isolated. Flagged for that diagnosis.

## Net effect

- 11 collection errors → **9** (cause-B1 cleared: 2 files, +282 tests verified green).
- Cause A (5 files): documented, operator decision pending.
- Cause B2 (4 files): import-path bug confirmed; fix reverted to avoid shipping a host-side
  hang; needs docker-harness validation + hanging-test isolation.
