## 2. Gap / Root Cause

### 2.1 Event Ingestion Allowlist Gap
`app/platform/event_ingestion/types.py` contained `VALID_EVENT_TYPES` — a frozenset allowlist. Any event type not in this set is **silently dropped** with a WARNING log:

```
record_event: unknown event type 'X' — skipped
```

All 9 Wave 1 event types were absent from this allowlist despite being registered in `app/platform/events/registry.py`. This caused 4/7 test failures: events were accepted at API level but never stored, so `summary_for_tenant()` returned zeros for all new event types.

### 2.2 Wrong Data Source for `course_fill_rate`
`refresh_tenant_metrics()` computed `total_enrollments` from `metric_values.get("total_enrollments")`, which is populated via `EVENT_METRIC_MAP` → analytics projection table (legacy path). The Wave 1 tests ingest enrollment data via the platform event ingestion path (`enrollment.created` → `event_counts`). The two paths do not share state, causing `course_fill_rate` to always return 0.

### 2.3 Regression Test Exclusion Sets Too Narrow
Two pre-existing tests in `test_platform_kpi_metrics_v1.py` asserted that all KPI cards *except* the 3 thresholded ones return `policy_pack=null` and `actionability_state=null`. The 5 new Wave 1 severity-thresholded KPIs broke this invariant.

## 5. KPI Source Correction

**`course_fill_rate` computation fix:**

Before:
```python
total_enrollments = int(metric_values.get("total_enrollments", 0) or 0)
```

After:
```python
total_enrollments = int(event_counts.get("enrollment.created", 0) or 0)
```

`event_counts` is the `summary_for_tenant()` output from the platform event ingestion layer — the same source all other Wave 1 KPIs use. The legacy `metric_values["total_enrollments"]` key is populated from a separate analytics projection store.
