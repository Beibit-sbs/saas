# A-056.R2 Hardening - Digital Twin Resource-Domain Review Remediation Report

## Scope

Remediate the confirmed findings from the compact adversarial review of the
A-056.10 resource-consumption domain. **3 findings, all 3 confirmed (0 refuted).**
All fixed, code + tests.

## Confirmed findings fixed

- **R2-F1 (HIGH) — `current_stock=NaN` returned HTTP 500.** Asymmetry: `current_stock`
  carried `Field(ge=0)` while `daily_consumption` was plain. `NaN >= 0` is False, so pydantic
  rejected NaN at the schema layer (before `_validate_finite`), and the 422 body echoing NaN
  then failed Starlette's `json.dumps(allow_nan=False)` -> 500. (Inf was masked because it
  passes `ge=0` and reaches the service.) **This is the exact bug class hardened in R1, re-introduced
  via the `ge=0` constraint** — caught only because the review ran per-node. **Fix:** make
  `current_stock` a plain `float`; `_validate_finite(current_stock, 0.0, 1e12, ...)` already enforces
  finiteness and `>= 0`, so NaN/Inf/1e400/negative all yield a clean 400.
- **R2-F3 (HIGH) — division overflow -> inf in a response.** Finite stock / tiny consumption
  (e.g. `1e12 / 1e-300`) produces `inf`; `round(inf, 2)` is `inf`, which serialises to a 500.
  **Fix:** validate the quotient is finite (`math.isfinite`) before rounding; non-finite -> clean 400.
- **R2-F2 (LOW) — classification used the ROUNDED days value.** A true pre-lead-time stockout just
  under the boundary (e.g. `69.96/10 = 6.996 < 7`) was downgraded to `reorder_point_reached` because
  `round(6.996, 2) = 7.0`. **Fix:** classify on the raw quotient; round only for the display field.

## Lesson

The per-node adversarial review caught a HIGH bug I had just hardened against in R1 and then
re-introduced through a single `ge=0`. The Ultracode loop (build -> review-workflow -> adversarial
verify -> remediate) is worth running on every new node, not just once per vertical.
