## ROOT CAUSE

Attendance risk signals (`academic.attendance_risk.detected`) were being detected and processed by Brain Core, but the policy guard was blocking autonomous dispatch because:

1. Academic risk signals classified as "critical" priority
2. Default tenant policy: `require_approval_for_critical=True`
3. Policy guard blocked dispatch when `priority=="critical"` AND `require_approval_for_critical==True`
4. Result: Interventions were planned but never dispatched

**Problem Pattern:**
```
signal.process_signal() 
  → classification: critical priority ✓
  → reasoning: recommended_actions=["create_intervention_case"] ✓
  → policy validation: requires_approval=True ✗
  → dispatch: SKIPPED (status="approval_pending" instead of "dispatched")
  → outcome: NO intervention case created
```

## IDEMPOTENCY & TENANT SAFETY

### Idempotency
- **Deduplication:** Brain Core signal deduplication (dedup_key hash) prevents duplicate signals
- **Case uniqueness:** Intervention service enforces one active case per student per risk type
- **Result:** Duplicate attendance signals → single intervention case (guaranteed)

### Tenant Isolation
- **Signal tenant_id:** Required field, validated before policy check
- **Decision tenant_id:** Preserved through reasoning/classification
- **Dispatch tenant_id:** Passed to dispatcher, enforced at case creation
- **Database query:** Intervention service filters by tenant_id on all operations
- **Result:** Tenant A attendance signals never create cases in Tenant B

### Security
- **Permission scope:** Attendance risk detection still requires student/academic access
- **Intervention creation:** Still uses existing interventions router with RBAC guards
- **No whitelist bypass:** Autonomous dispatch is policy-level, not permission-level
- **Audit:** Existing audit trail captures all created cases and actions
