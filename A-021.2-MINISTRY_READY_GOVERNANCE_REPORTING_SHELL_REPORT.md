# A-021.2 — Ministry-Ready Governance Reporting Shell Report

## Scope
A-021.2 packages existing rector/admin KPI evidence into a read-only, tenant-scoped governance reporting shell. It does not add ministry submission, external integration, fake KPI data, or destructive actions.

## Implementation Summary
- Added a ministry-ready governance reporting shell to [frontend/app/(admin)/console/dashboard/page.tsx](frontend/app/(admin)/console/dashboard/page.tsx).
- The shell reuses the existing tenant snapshot from `useRectorDashboard` and renders missing values as `Not available`.
- Added dashboard coverage in [frontend/__tests__/admin/RectorDashboardPage.test.tsx](frontend/__tests__/admin/RectorDashboardPage.test.tsx) for read-only wording, section rendering, and empty-snapshot stability.

## Repo Hygiene Snapshot
- Existing unrelated local artifacts were left untouched: `.coverage`, `backend/.coverage`, `.vscode/tasks.json`, historical A-011/A-012/A-017 reports, `A009_AUTH_HARNESS_STABILIZATION.md`, and `infra/nohup.out`.
- No destructive repo cleanup was performed.

## Contract / Gap Matrix
- Backend ministry KPI contract already existed in [backend/app/platform/kpi/ministry_kpi.py](backend/app/platform/kpi/ministry_kpi.py); no backend contract change was needed for the shell.
- Frontend dashboard already consumed tenant-scoped KPI data through `useRectorDashboard`, so the shell could be added without a new endpoint.
- The shell is intentionally advisory-only: no external submission, no auto-approval, no schedule mutation, no procurement mutation, and no fake metrics.

## Safety Proof
- Read-only: the shell only renders existing dashboard evidence.
- Tenant-scoped: it uses the authenticated tenant snapshot already loaded by the dashboard.
- Evidence-backed: every displayed value is sourced from the current KPI payload or shown as `Not available`.
- Non-destructive: the shell does not trigger backend writes, external submissions, or state-changing actions.
