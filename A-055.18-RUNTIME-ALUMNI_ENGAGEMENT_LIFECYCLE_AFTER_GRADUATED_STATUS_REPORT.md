# A-055.18 Runtime - Alumni Engagement Lifecycle After Graduated Status Report

## Scope

Continue the post-graduation branch after the guarded student status transition:

```text
graduated student -> alumni record -> engagement lifecycle -> Brain/KPI visibility
```

## Result

The backend already had the core alumni rules:

- alumni records can only be created for graduated students,
- engagement caps prevent inflated activity records,
- status transitions are constrained,
- `engaged` creates an engagement event,
- `inactive` emits risk signals and creates a disengagement risk alert,
- `/api/admin/alumni/brain-context` exposes aggregate alumni context.

This slice made that lifecycle visible and usable in the admin console:

- Added frontend type/hook for alumni Brain context.
- Added alumni KPI cards for total records, engaged, donors, and risk level.
- Added status filters: all, active, engaged, donor, inactive.
- Expanded row actions from only `Mark engaged` to all allowed lifecycle transitions:
  - active -> engaged, donor, inactive
  - engaged -> donor, inactive
  - donor -> engaged, inactive
  - inactive -> active
- Guarded create/update UI actions with `alumni.write`.
- Kept the graduated-student selector from A-055.17 as the creation entrypoint.
