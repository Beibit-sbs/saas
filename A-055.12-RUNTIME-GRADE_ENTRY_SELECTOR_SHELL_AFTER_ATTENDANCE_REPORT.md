# A-055.12 Runtime Grade Entry Selector Shell After Attendance Report

Date: 2026-06-18

## Scope

Twelfth correction slice after attendance:

```text
section attendance
  -> enrollment-backed grade entry
  -> grade submit/change lifecycle
```

The goal of this slice was to stop grade entry from depending on a raw, legacy `PUT /grades` contract and connect it to the existing backend grade lifecycle.

## Changed Files

Backend:

- `backend/app/modules/grades/router.py`
- `backend/app/modules/grades/service.py`

Frontend:

- `frontend/app/(admin)/console/grades/page.tsx`
- `frontend/modules/grades/api.ts`
- `frontend/modules/grades/hooks.ts`
- `frontend/modules/grades/types.ts`
- `frontend/__tests__/admin/GradesPage.test.tsx`
- `frontend/__tests__/admin/Wave2KpiPages.test.tsx`

## Result

Grades page now follows the current academic runtime chain:

```text
tenant admin
  -> student enrollment
  -> lesson attendance
  -> grade entry by enrollment selector
```

Backend now exposes a tenant-level grade list endpoint:

```text
GET /api/admin/grades
```

with optional filters:

```text
student_profile_id, course_id, term_id, section_id, page, page_size
```

Frontend grade mutations now call the canonical lifecycle endpoints:

```text
POST  /api/admin/grades/submit
PATCH /api/admin/grades/change
```

The Add Grade drawer now:

- loads enrolled enrollments
- loads active students for readable labels
- lets the operator choose an enrollment instead of typing the enrollment id when data is available
- keeps manual enrollment id fallback if the list is empty
- includes `grading_scale_id`, because backend grade lifecycle requires a grading scale

Example selector label:

```text
S-1001 / Aida Karim / Course #22 / Term #7 / Section #55 / Enrollment #9001
```

## Current Limits

The grade scale is still entered as `Grading scale ID`.

This is intentional for this slice: backend already has grade scale tables and validation, but there is not yet a frontend scale catalog/selector shell in this runtime path.
