# A-046.COV-R2 - Coverage Denominator Expansion and True Baseline Analysis Report

## 1. Executive Summary
A-046.COV-R2 measured the current 42.12% backend coverage baseline against the latest historical 87% era and segmented the codebase into core, preexisting, new-vertical, expansion, provider-readiness, and legacy buckets.

Primary conclusion:
- The coverage drop is not primarily caused by new vertical denominator growth.
- The strongest driver is low coverage inside preexisting and legacy modules, with denominator expansion acting as a secondary factor.
- The correct classification is `SCENARIO_C: MIXED`.

Key results:
- Historical coverage family: 87.07% to 87.89%
- Current full-backend coverage: 42.12%
- Historical-comparable files under current code: 36.20%
- Core-only coverage (core platform + high-coverage preexisting 87-era modules): 58.50%
- Legacy-excluded forecast: 59.07%
- New-verticals-excluded forecast: 37.28%

This means the current 42.12% is only partially comparable to the historical 87% family: the codebase is larger, but the older file set also now covers far less than it did historically.

## 9. True Baseline Classification
Chosen scenario:
- `SCENARIO_C: MIXED`

Why not Scenario B denominator expansion only:
- If denominator expansion were primary, historical-comparable current coverage would remain near the 87% family.
- It does not. It is 36.20%.

Why not Scenario A pure collapse only:
- The codebase did grow by 25.49%, and new verticals/expansion/provider slices add real denominator.
- So there is a comparability problem, but it is not the dominant one.

Why not Scenario D not comparable at all:
- The harness lineage is still comparable enough to reason from.
- The newer denominator matters, but the older file set has also degraded substantially.
