# A-056.7 Runtime - Digital Twin Live Classroom Capacity Report

## Scope

Wire `classroom_capacity` to a LIVE read (sum of `campus_rooms.capacity`),
mirroring the A-056.4 enrollments pattern, so the capacity projection,
early-warning, and scenario registry all run on real room capacity when
`use_live_sources` is set. Read-only, best-effort, honest fallback.

## Result

- Service helper `_live_classroom_capacity(tenant_id)`: best-effort sum of
  `campus_rooms` capacity via the shared `list_entities_for_tenant("campus_rooms", tenant_id)`
  (same clean tenant-scoped store path as enrollments); returns `None` on any
  failure or when no rooms exist.
- `simulate_capacity`: when `use_live_sources` and the live read resolves,
  `classroom_capacity` is overridden, evidence is tagged `mode="live"` /
  `source_module="campus_rooms"`, and `live_sources_used` includes `"campus_rooms"`.
  On failure it falls back to the caller value (`mode="caller_provided"`,
  `source_module="scheduling"`) — no fabrication.
- This propagates automatically to the early-warning (.5) and scenario registry
  (.6) since both reuse `simulate_capacity`.
- Frontend copy updated to note both live sources.

## Safety / Honesty

- No fabricated values: live or caller-provided, always tagged. Missing source →
  honest fallback / incomplete_data.
- Read-only; `fake_metrics=false`; no autonomous action; viewer denied.
- No new route/permission/schema (route count remains 5, permission 3) — additive
  behavior inside the existing what-if.
