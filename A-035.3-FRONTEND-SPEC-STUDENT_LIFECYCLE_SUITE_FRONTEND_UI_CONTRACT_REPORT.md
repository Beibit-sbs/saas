# A-035.3-FRONTEND-SPEC - Student Lifecycle Suite Frontend UI Contract Report

## 1. Executive Summary

A-035.3-FRONTEND-SPEC defines the Student Lifecycle Suite frontend UI contract on top of A-035.2-B1 commit `7fe068e`. This action specifies the future module structure, route map, page contracts, component surface, type/API/hook/guard contracts, sensitive UI labels, frontend test plan, future E2E plan, anti-fake boundaries, and the recommended runtime subset. This action is spec-only and docs-only.

## 6. Page Contracts

### Overview

- route: `/console/student-lifecycle`
- endpoint: `GET /api/admin/student-lifecycle/dashboard`
- permission: `student_lifecycle.dashboard.read`
- core UI: dashboard cards, status breakdown, review queue, limitations panel
- sensitive labels: `fake_metrics=false`, `data_source=computed_from_student_lifecycle_metadata`, `automated_decision_count=0`, `hidden_score_present=false`
- constraints: navigation-only first, no auto decisioning

### Applicants

- route: `/console/student-lifecycle/applicants`
- endpoint: `GET /api/admin/student-lifecycle/applicants`
- permission: `student_lifecycle.applicants.read`
- core UI: applicant registry, status timeline, human-review badge
- sensitive labels: `Human review required`, `No automated decision is made`, `Metadata only`
- constraints: no autonomous admission decision, no ranking UI

### Students

- route: `/console/student-lifecycle/students`
- endpoint: `GET /api/admin/student-lifecycle/students`
- permission: `student_lifecycle.students.read`
- core UI: student registry, profile summary, status timeline
- sensitive labels: `Demo/pilot data must not contain real student data`, `Provider integration not enabled`
- constraints: no SIS replacement claim, no live roster sync

### Enrollment

- route: `/console/student-lifecycle/enrollment`
- endpoint: `GET /api/admin/student-lifecycle/enrollment`
- permission: `student_lifecycle.enrollment.read`
- core UI: enrollment dashboard, detail panel, review panel
- sensitive labels: `Registrar review required`, `Audit-backed transition`
- constraints: no automated registrar approval

### Academic Records

- route: `/console/student-lifecycle/academic-records`
- endpoint: `GET /api/admin/student-lifecycle/academic-records`
- permission: `student_lifecycle.records.read`
- core UI: record registry, detail panel, metadata-only/source notices
- sensitive labels: `No fake grades`, `Source unavailable`, `Metadata only`
- constraints: no synthetic grades or unsupported source claims

### Transcript Preview

- route: `/console/student-lifecycle/transcripts`
- endpoint: `GET /api/admin/student-lifecycle/transcripts`
- permission: `student_lifecycle.transcripts.read`
- core UI: transcript preview registry and preview panel
- sensitive labels: `Unofficial preview`, `Official document not issued`, `Digital signature not enabled`, `No fake transcript`
- constraints: no official transcript issuing, no provider dispatch

### Degree Progress

- route: `/console/student-lifecycle/degree-progress`
- endpoint: `GET /api/admin/student-lifecycle/degree-progress/{student_id}` or aggregate equivalent
- permission: `student_lifecycle.degree_progress.read`
- core UI: degree progress dashboard, readiness panel, incomplete-data notice
- sensitive labels: `Computed from available sources`, `Incomplete data possible`, `Advisor review required`, `No automatic graduation eligibility decision`
- constraints: no automatic graduation pass/fail

### Requests

- route: `/console/student-lifecycle/requests`
- endpoint: `GET /api/admin/student-lifecycle/requests`
- permission: `student_lifecycle.requests.read`
- core UI: request registry and review panel
- sensitive labels: `Human review required`, `Decision metadata only`, `No automated decision is made`
- constraints: no auto approve or auto reject

### Appeals

- route: `/console/student-lifecycle/appeals`
- endpoint: `GET /api/admin/student-lifecycle/appeals`
- permission: `student_lifecycle.appeals.read`
- core UI: appeal registry and review panel
- sensitive labels: `Decision metadata only`, `Human reviewer required`, `No autonomous decision`
- constraints: no autonomous appeal decision

### Interventions

- route: `/console/student-lifecycle/interventions`
- endpoint: `GET /api/admin/student-lifecycle/interventions/plans`
- permission: `student_lifecycle.interventions.read`
- core UI: intervention dashboard, plan panel, follow-up timeline
- sensitive labels: `Support visibility only`, `No hidden risk score`, `No discriminatory score`, `No punitive automation`
- constraints: no punitive automation or hidden ranking

### Audit

- route: `/console/student-lifecycle/audit`
- endpoint: `GET /api/admin/student-lifecycle/audit`
- permission: `student_lifecycle.audit.read`
- core UI: audit log, evidence metadata, audit trail panel
- sensitive labels: `Audit-backed transition`, `Metadata only`, `No hard delete`
- constraints: no destructive purge controls

Detail routes inherit the same boundary rules and should be deferred if runtime scope becomes tight rather than being filled with fake static data.
