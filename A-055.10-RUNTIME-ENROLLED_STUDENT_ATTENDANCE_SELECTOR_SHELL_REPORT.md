# A-055.10 Runtime Enrolled Student Attendance Selector Shell Report

Date: 2026-06-18

## Scope

Tenth correction slice after lesson instance selector:

```text
selected section
  -> enrollments in section
  -> enrolled student selector
  -> mark attendance
```

The goal of this slice was to remove manual student profile id typing from attendance marking when section enrollments are available.

## Backend Result

Enrollments now exposes a tenant-scoped general list endpoint:

```text
GET /api/admin/enrollments
```

Supported filters:

```text
page
page_size
status
student_profile_id
course_id
term_id
section_id
```

This makes section attendance workflows able to load the enrolled students for a concrete section without relying on raw database access or unrelated roster endpoints.

## Frontend Result

Scheduling page now:

- loads enrollments for the selected section
- filters attendance candidates to enrolled students
- shows enrolled students as attendance choices
- keeps manual student profile id fallback only when no enrolled students are loaded
- clears selected student when section changes

Attendance marking now follows:

```text
select section
  -> select/create lesson
  -> select enrolled student
  -> mark attendance
```

## Test Coverage Added

`SchedulingPage.test.tsx` now verifies:

- enrolled student selector renders when section enrollments are available
- enrollment option includes student profile id and enrollment id

## Current Limits

The next clean slice should improve operator readability:
