# A-055.2 Runtime SaaS Root Tenant Admin Login Workspace Report

Date: 2026-06-18

## Scope

Second correction slice for the SaaS root entrypoint:

`platform superadmin -> create university tenant -> create tenant admin -> login tenant admin -> tenant-scoped workspace context`

## Contract Confirmed

Backend login is tenant-bound:

- `/api/auth/login` requires `X-Tenant-ID`
- local authentication rejects users whose stored `tenant_id` does not match the header
- access token stores the tenant in `tid`
- `/api/auth/me` returns `user.tenantId`

Frontend login sends:

- `X-Tenant-ID` header
- tenant id in request body for backward compatibility
- redirects to `/console` after successful login

`/console` resolves to the dashboard and the topbar reads `tenantId` from the authenticated session.
