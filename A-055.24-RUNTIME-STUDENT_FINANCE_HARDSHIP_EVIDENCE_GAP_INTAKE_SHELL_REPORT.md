# A-055.24 Runtime - Student Finance Hardship Evidence Gap Intake Shell Report

## Scope

Add metadata-only evidence gap intake for finance-origin hardship reviewer queue items:

```text
reviewer queue item -> evidence gap metadata intake -> updated readiness state
```

## Result

Added a guarded intake endpoint:

- Backend route:
  - `POST /api/admin/student-services/hardship/from-finance-handoff/{hardship_id}/evidence-gap`
- Backend permission:
  - guarded by `admin.student_services.write`
- Backend behavior:
  - verifies tenant scope,
  - verifies the hardship record came from `student_finance_receivables_handoff`,
  - stores evidence metadata in hardship `metadata_json`,
  - removes the satisfied gap from `missing_evidence_json`,
  - updates readiness to `ready_for_human_review` when gaps are cleared,
  - emits `hardship.finance_handoff_evidence_gap_intake`.
- Frontend API:
  - `intakeFinanceHardshipEvidenceGap(...)`
- Frontend dashboard shell:
  - shows the evidence gap intake endpoint and expected metadata fields beside each reviewer queue item.

## Safety Boundaries

The intake is evidence metadata only.

It does not approve aid, reject aid, cancel debt, mutate billing balances, execute payments, create fake evidence, submit to providers, or call external systems.

Explicitly preserved:

- `noAutomaticAidDecision=true`
- `noBillingBalanceMutation=true`
- `humanReviewRequired=true`
- `fake_metrics=false`
- `provider_live_enabled=false`
- `autonomous_decision_enabled=false`
- `hidden_score_present=false`
