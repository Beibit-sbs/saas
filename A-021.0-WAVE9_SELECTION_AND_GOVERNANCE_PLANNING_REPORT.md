## 9. Governance Safety Model

### Allowed

- Read-only executive summaries
- KPI aggregation from evidence-backed sources
- Domain health cards and cross-domain risk heatmap
- Evidence drilldown contracts
- Governance review/actionability queue (human-reviewed)
- Ministry reporting shell/export-ready governance contract
- Human approval/review signals and escalation indicators

### Forbidden

- Automatic disciplinary actions
- Automatic security lockout/ban
- Automatic schedule mutation
- Automatic room assignment
- Automatic procurement/finance approval
- Silent cross-tenant aggregation
- Fake KPI/demo values
- RBAC/tenant isolation bypass

### Safety enforcement constraints

- Governance dashboard remains decision-support first
- No hidden auto-actions
- Tenant context is authoritative for every read path
- Missing optional metrics must degrade gracefully (null-safe rendering)

## 10. Recommended A-021 Direction

### Option 1 - Ministry / Rector Governance Dashboard

Pros:

- Highest demo/sales readiness
- Packages existing mature domains into executive narrative
- Aligns with productization and ministry conversation needs
- Reuses current KPI/dashboard/event/Brain foundations

Cons:

- Requires strict information architecture to avoid dashboard bloat
- Requires careful governance-safe aggregation policy

### Option 2 - Human-Approved Timetable Change Workflow

Pros:

- Strong technical depth continuation after A-020
- Operationally meaningful for scheduling governance

Cons:

- Higher operational/control complexity (approvals, rollback, simulation)
- Narrower executive demo breadth versus governance dashboard

Decision:

- Recommended theme for A-021: Option 1 (Ministry / Rector Governance Dashboard)
- Option 2 remains a strong next-wave candidate after governance packaging stabilizes

## 11. Risks / Stop Rules

### Key risks

- Dashboard sprawl and duplication of module pages
- Inconsistent severity semantics across domains
- Overexposure risk in ministry reporting without strict suppression/whitelisting
- Alert fatigue in governance queue without bounded prioritization

### Stop rules

- Stop if any design introduces destructive operations from governance layer
- Stop if cross-tenant data can be aggregated without explicit authority controls
- Stop if KPI values cannot be traced to evidence lineage
- Stop if dashboard contract cannot tolerate missing optional metrics
