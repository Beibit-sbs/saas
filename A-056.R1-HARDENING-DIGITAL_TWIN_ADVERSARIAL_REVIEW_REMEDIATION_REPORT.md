# A-056.R1 Hardening - Digital Twin Adversarial-Review Remediation Report

## Scope

Remediate the confirmed findings from a multi-agent adversarial review of the
Digital Twin vertical (A-056.1-.9). The review produced 23 candidate findings;
each was independently verified (default-refute). **15 confirmed, 8 refuted.**
All 15 are fixed here, code + tests.

## Confirmed findings fixed

### HIGH
- **F1/F2 — non-finite input -> HTTP 500.** `intake_growth_percent` / `intake_growth_scenarios`
  accepted `inf`/`nan` (e.g. JSON `1e400`); `round(inf)`/`int(inf)` raised an unhandled
  OverflowError -> 500 on `/simulate/capacity`, `/early-warning/capacity`, `/scenarios/capacity`.
  Note: a pydantic constraint alone is insufficient — the 422 error body echoes `inf`, which
  Starlette's `json.dumps(allow_nan=False)` then fails to serialise. **Fix:** accept the float
  into the model (plain `float`) and validate finiteness + range in the service
  (`_validate_finite`), mapped by the router (`_guard`) to a clean **400** (no `inf` in any
  response body). Applied to growth + housing_demand_ratio + scenario elements.
- **F3 — decision read-back had no tenant-isolation assertion.** Added asserts that
  `list_admin_actions`/`log_admin_action` are called with `tenant_id == 1` and not
  `include_all_tenants`.
- **F4 — tenant fail-closed only tested on `/state`.** Added a parametrized test covering ALL 7
  routes x 6 bad tenant values (None/0/-1/bool/float/str) -> 400. (42 cases pass.)

### MEDIUM
- **F5 — live classroom capacity of 0 silently overrode a valid caller value.** `_live_classroom_capacity`
  now returns `None` for a non-positive total, and the service override is `if live_cap:` (truthy)
  so 0/None fall back honestly.
- **F6/F7/F8/F9 — coverage gaps.** Added tests: live-classroom fallback (mode caller_provided),
  negative growth (-50/-100 deterministic), boundary util exactly 1.0 (no warning) and 1.2 (medium
  not high), dormitory incomplete branch.
- **F10 — nav permission granted to no role (vertical unreachable in prod).** `digital_twin` perms
  were never unioned into any role baseline, so real superadmin/admin users got 403 and the nav
  link was hidden. Imported `digital_twin.permissions.ALL_PERMISSIONS` into `rbac/service.py` and
  unioned it into the superadmin and admin baselines (mirroring campus/security).

### LOW
- **F11 — read log guarded by the write permission.** Added `digital_twin.decision.read` and
  guarded `GET /scenarios/decisions` with it (least-privilege; distinct from `decision.record`).
- **F12/F13/F14 — weak/absent assertions.** Added: read-only routes never call
  `log_admin_action`; both live sources -> both tagged `live` + `provider_live_enabled` stays
  False; custom/negative scenario names+projections deterministic.
- **F15 — page omitted `provider_live_enabled`.** Added to the page SAFETY_FLAGS + test so the
  declared flag set matches `DigitalTwinSafetyFlags`.

## Refuted (8) — verification rejected as non-issues
Scenario name collisions; decision-log defense-in-depth duplication; several "fake_metrics
unenforced"/"mode live mismatch"/"provider flag not reconciled" framings; record-without-prior-sim;
router-swallows-ValueError — each refuted on the code (already-handled or not a real defect).
