# A-015.3 — PURCHASE ORDER → DELIVERY → ASSET INVENTORY CHAIN
## Evidence Report · CLOSED-PASS

### Summary
Moved procurement asset-inventory auto-creation from the `PO_ISSUED` FSM step to the `DELIVERED` step,
ensuring the asset record is only created when goods/services are confirmed delivered—not when the PO
is merely issued. The change is additive-only: no new migrations, no new endpoints, no breaking API changes.

### Invariants Preserved

- **Fail-closed**: `tenant_id == 0` or missing `contract_code` → `DomainValidationError`
- **Idempotent**: duplicate DELIVERED delivery for same contract does not create a second asset record
- **Audit lineage**: `procurement.delivered` + `procurement.asset_created` events emitted with matching `contract_id`, `contract_code`, `asset_id`, `asset_code`, `vendor_code`
- **No migration**: no new DB columns, no schema changes
- **No new endpoints**: purely internal service logic

---

### FSM Note

Valid predecessor chain for asset creation:
```
DRAFT → APPROVED → PO_ISSUED → DELIVERED  ← asset created here
```
`APPROVED → DELIVERED` is an invalid FSM transition and correctly raises `ValueError` before any side effects.
