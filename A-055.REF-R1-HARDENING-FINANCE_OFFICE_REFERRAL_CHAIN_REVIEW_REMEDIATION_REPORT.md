# A-055.REF-R1 Hardening - Finance-Office Referral Chain Review Remediation Report

## Scope

Remediate confirmed findings from the adversarial review of the money-adjacent
finance-office referral chain (A-055.26-.31). The review produced 13 findings;
each independently verified (default-refute). **8 confirmed, 5 refuted.**

## The serious one (5 findings, one root cause)

**The A-055.29 acknowledge endpoint was completely broken — HTTP 500 on EVERY
authorized call, and the acknowledgement ledger could never reflect a record.**

Root cause: `acknowledge_student_finance_referral` wrote via
`_create_metadata_record(family="student_finance_referrals", ...)`, but
`MODEL_BY_FAMILY` has no such key — `repository.create_family_row` did
`MODEL_BY_FAMILY["student_finance_referrals"]` -> **KeyError** -> the router's
`_handle` (which only maps TenantResourceNotFoundError/DomainValidationError/ValueError)
re-raised it -> **HTTP 500**. The existing test only asserted the viewer->403 path
(denied before the service runs), so a successful acknowledge was never exercised
and the bug shipped uncaught. Even if the KeyError were fixed naively, the write
set no `bridge_family`, so `GET /bridges/student-finance-referrals` (which filters
`FinanceBridgeRecord.bridge_family == "student_finance_referrals"`) would never show it.

**Fix (findings F1/F2/F3/F5/F6):** persist a `FinanceBridgeRecord` via
`family="bridges"` with `extra={bridge_family:"student_finance_referrals",
target_domain:"student_finance", read_only_first:True, mutation_allowed:False,
metadata_json:{...acknowledgement details...}}` — the exact `bridge_family` the GET
ledger reads — so acknowledge succeeds AND round-trips into the ledger.

**Fix (F4):** the acknowledge response now surfaces the anti-fake flags
(`no_automatic_aid_decision`, `no_billing_balance_mutation`, `no_payment_execution`,
`human_review_required`) + `bridge_family`, which the prior return omitted.

**Fix (F7):** added a positive test: admin POST acknowledge -> 201 (not 500),
response carries the anti-fake flags, and a `FinanceBridgeRecord` with
`bridge_family="student_finance_referrals"` is persisted.

## Lesson

A test that only asserts the DENIED path (viewer->403) gave false confidence — the
success path was never executed, so a 100%-failure endpoint shipped "green". The
adversarial review reproduced the success path and caught it. Every write endpoint
needs a positive (authorized-success) test, not just an RBAC-denial test.
