# A-025.3 — Rector KPI Drilldown to Domain-Level Evidence

## Executive Summary

A-025.3 delivers the first "killer workflow" for rector users: a read-only, tenant-scoped, deterministic drilldown from top-level KPI cards into domain-level evidence sources. The implementation surfaces existing `RECTOR_KPI_EVIDENCE_DRILLDOWN_CONFIG` (8 domains, already defined but never wired) via a new API endpoint and a new frontend panel, backed by 18 backend + 6 new frontend tests (total 29 frontend tests pass).

**No DB mutations. No policy enforcement. No autonomous decisions. No fake values.**

## Implementation Scope

### Backend Changes

#### `backend/app/platform/kpi/service.py`
- `get_rector_dashboard()` — now populates `drilldowns` key in snapshot payload by calling `_build_rector_kpi_evidence_drilldowns()`
- `get_rector_kpi_drilldown(*, tenant_id, uow)` — NEW public function:
  - Validates `tenant_id > 0` (raises `ValueError` otherwise)
  - Fetches snapshot via `get_rector_dashboard()`
  - Calls `_build_rector_kpi_evidence_drilldowns(cards=...)`
  - Returns full summary dict with safety flags

#### `backend/app/platform/kpi/schemas.py`
- Added `RectorKpiDrilldownSummarySchema` after existing `RectorDashboardReadSchema`
- Fields: `tenant_id`, `snapshot_date`, `generated_at`, `domains`, `total_domains`, `review_required_count`, `unavailable_domains_count`, `critical_domains_count`, `high_domains_count`, `source`, `readonly`, `tenant_scoped`, `no_policy_enforcement`, `no_autonomous_decision`, `no_remediation_action`

#### `backend/app/platform/router_admin.py`
- Import updated to include `RectorKpiDrilldownSummarySchema`
- New endpoint: `GET /platform/kpi/drilldown` (full path: `/api/v1/admin/platform/kpi/drilldown`)
  - Query param: `tenant_id: int`
  - Response model: `RectorKpiDrilldownSummarySchema`
  - Auth: platform admin required

### Frontend Changes

#### `frontend/modules/platform/kpi/types.ts`
- Added `RectorKpiEvidenceSource` interface
- Added `RectorKpiEvidenceDrilldown` interface  
- Added `RectorKpiDrilldownSummary` interface

#### `frontend/modules/platform/kpi/use-dashboard.ts`
- Added `PLATFORM_KPI_DRILLDOWN_KEY = "platform-kpi-drilldown"` constant
- Added `useRectorKpiDrilldown(tenantId: number)` React Query hook
  - `enabled: tenantId > 0`
  - `staleTime: 60_000`
  - Fetches `/api/bff/admin/platform/kpi/drilldown`

#### `frontend/app/(admin)/console/dashboard/page.tsx`
- Import added for `useRectorKpiDrilldown`
- New `riskBadgeClass` helper constant
- New `RectorKpiDrilldownPanel` component:
  - `data-testid="rector-kpi-drilldown-panel"`
  - Shows header with read-only annotation
  - Shows summary counts grid (`data-testid="rector-kpi-drilldown-summary-counts"`)
  - Shows domains grid (`data-testid="rector-kpi-drilldown-domains"`)
  - Each domain: `data-testid=rector-kpi-drilldown-domain-{domain_id}`
- Rendered in dashboard between `<KpiEvidenceDrilldownContract>` and `<AutomationOverviewWidget>`

## No-Fake-Value Confirmation

When a metric is unavailable (no card in snapshot), the domain is marked `status: "unavailable"` with `evidence_sources: []`. No placeholder values, no synthesised scores, no default evidence entries are injected.

---

## Tenant Isolation Confirmation

- `tenant_id` is validated as `> 0` before any data access (fail-closed)
- `tenant_id` is passed through the full call chain from API endpoint → service → snapshot fetch
- All evidence is sourced from the tenant's own KPI snapshot only
- Response includes `tenant_id` echo for caller verification
