## 1. Objective

Wire the Brain Core thesis risk path so that:
- Risky thesis status transitions (`rejected`, stalled `> 60 days`) create an idempotent `create_intervention_case` action instead of only a supervision task.
- Duplicate thesis risk signals do not create duplicate intervention cases.
- Thesis-risk origin (thesis_id, to_status, source_entity_id) is preserved in the action plan evidence.
- Missing `tenant_id` / `student_id` / `thesis_id` fail closed (no intervention created).
- Cross-tenant leakage is impossible.
- `AcademicChainEventHandler` does not duplicate intervention creation for the same event when Brain Core has already routed it.

## 4. Architectural Notes

### Duplicate consumer resolution
The `AcademicChainEventHandler` previously created an intervention case via outbox consumer on `thesis.status_changed with to_status=rejected`. Now that Brain Core processes the same event via direct `process_signal()`, the outbox handler is bypassed with the `brain_core_routed` flag in the outbox payload. This is additive and backwards-compatible: existing events without the flag continue to be handled by the old handler.

### Reuse pattern
Follows the existing pattern in `grades/service.py` and `admissions/service.py`:
1. Publish outbox event (async, for downstream consumers).
2. Call `brain_core_service.process_signal()` fire-and-forget (synchronous but exception-safe).

### No new DB migrations required
No new tables or columns. The `brain_core_routed` field is carried in the existing `payload_json` column of the outbox.
