# A-055.29 Runtime - Finance-Office Referral Acknowledgement Note Report

## Scope

Let a finance reviewer record a metadata-only, non-executing acknowledgement of a student-services finance-office referral:

```text
student-services referral -> finance reviewer acknowledgement note -> no financial action
```

## Result

Added a finance-side acknowledgement write, mirroring the existing review POST pattern (`review_budget_control`):

- Backend route:
  - `POST /api/admin/finance-procurement-asset/bridges/student-finance-referrals/acknowledge`
- Backend permission:
  - new `finance_procurement_asset.bridges.student_finance.acknowledge` (distinct write permission; RBAC-correct for a POST)
- Backend service:
  - `acknowledge_student_finance_referral` -> `_create_metadata_record(..., "student_finance_referrals", status_default="HUMAN_REVIEW_REQUIRED", extra={acknowledgement_state, no_automatic_aid_decision, no_billing_balance_mutation, no_payment_execution})`
  - records the acknowledgement as a tenant-scoped bridge metadata row plus an audit event.
- Frontend:
  - new API client `acknowledgeFpaStudentFinanceReferral`
  - acknowledgement shell inside the student-finance referral intake panel declaring the POST endpoint and non-executing semantics.

## Safety Boundaries

The acknowledgement is a note only.

It does not approve aid, reject aid, cancel debt, create tuition charges, mutate billing balances, execute payments, or post to ERP.

Explicitly preserved:

- `acknowledgement_state=non_executing_acknowledged`
- `noAutomaticAidDecision=true`
- `noBillingBalanceMutation=true`
- `noPaymentExecution=true`
- `humanReviewRequired=true`

## Current Runtime Meaning

The finance-office referral round trip now has a human acknowledgement step
on the finance side:

```text
finance receivables handoff -> student-services hardship review ->
finance-office referral -> finance read-only intake ->
finance reviewer non-executing acknowledgement
```

Every hop is metadata-only and human-gated.
