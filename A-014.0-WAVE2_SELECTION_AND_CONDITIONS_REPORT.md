### 4.1 Feature 1 — Grade Decline Intervention Loop

**Why selected:**  
Highest overall score (33). The `grades` module already publishes `academic.grade_risk.detected` (fully in the Wave 1 event registry and Brain registry). The action bridge already creates intervention cases. This feature closes the full loop: grade risk → Brain decision → intervention auto-create → KPI update. Zero new event type registration needed.

**Modules involved:**
- `grades` (signal source)
- `brain_core` (classifier, decision, action bridge)
- `interventions` (action target — case creation)
- `platform/kpi` (outcome KPI)
- `rbac` (access control)

**Existing code to reuse:**
- `academic.grade_risk.detected` already in `VALID_EVENT_TYPES` and Brain registry
- `action_bridge.py` — `make_create_intervention_case_handler` (built in A-013.1)
- `composite_risk_scorer.py` — grade score component (`_grade_risk_score`)
- `early_warning_sweep.py` — sweep already pulls grade signal
- `kpi/service.py` — `student_success` KPI section already includes grade metrics

**Likely missing links:**
- Brain rule in `rules_engine.py` explicitly for `academic.grade_risk.detected` → `CREATE_INTERVENTION` action
- Severity mapping for grade risk levels (currently only attendance has explicit intervention action)
- KPI metric for "grade decline intervention rate" in Wave 2 KPI section

**Brain Core role:**  
Classifier maps grade risk severity (high/critical = intervention dispatch). Decision policy routes to `CREATE_INTERVENTION` action. Action bridge writes intervention case. Outcome listener updates KPI.

**KPI/output:**  
- `grade_decline_intervention_rate` (cases created per grade risk signal)
- `grade_risk_signal_volume` (event count per tenant per period)
- Integration with existing `student_success` KPI section

**Risk:**  
Low. All infrastructure exists. Primary risk: grade risk signal rate may be high in production if thresholds not tuned — mitigated by dedup in `action_bridge.py`.
