### 2) Service Hardening and Lifecycle Closure

Updated `backend/app/modules/events_management/service.py`:
- enforced required fields with non-empty guards (`title`, `category_id`, `organizer_id`, `start_time`, `end_time`)
- added ISO datetime parsing and schedule window validation (`start_time < end_time`)
- added compatibility wrappers for tenant-entity API call signatures (table-first and tenant-first)
- added audit logging and usage metric recording hooks (fail-safe)
- lifecycle events now emitted for:
  - `event.created`
  - `event.published`
  - `event.registration_opened`
  - `event.registration_full`
  - `event.started`
  - `event.completed`
  - `event.cancelled`
- registration hardening:
  - duplicate registration guard per `(event_id, student_id)`
  - numeric capacity parsing guard
  - capacity reached guard
- retained/extended fail-closed tenant validation and invalid-transition rejection
