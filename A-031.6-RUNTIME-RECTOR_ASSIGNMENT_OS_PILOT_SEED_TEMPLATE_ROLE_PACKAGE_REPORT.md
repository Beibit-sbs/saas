## 3. Implementation Mode Decision

**Option A selected**: Pure Python data module (no DB writes, no external calls).

This was selected over Option B (DB-write seed) and Option C (migration) because:
- The project's existing `seeds.py` pattern is pure Python data dicts with no DB-write mechanism.
- Option A has no side effects, is fully testable in isolation, and is safe to run in any environment.
- A DB-write seed would require a live database session, increasing coupling and risk.

## 20. Anti-Fake Declaration

This implementation:
- Does NOT write to any database
- Does NOT call any external provider (email, SMS, etc.)
- Does NOT include any real personal data
- Does NOT claim production readiness
- Does NOT claim L5/L6 elevation
- Does NOT enable autonomous escalation
- Does NOT include any passwords, tokens, or secrets
- Uses only placeholder usernames and @pilot.local email addresses
- Uses `PILOT_TENANT_PLACEHOLDER` — no hardcoded production tenant ID

All anti-fake guarantees are enforced by module-level constants and validated by `validate_pilot_package()`. The validation function will return FAIL if any of these constants are modified to True.
