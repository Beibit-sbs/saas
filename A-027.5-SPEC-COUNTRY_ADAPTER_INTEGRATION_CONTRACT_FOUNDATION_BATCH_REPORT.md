## 4. Kazakhstan-First but Saudi/GCC-Ready Strategy

- Kazakhstan provider profiles are the first activation set.
- Core module names remain country-neutral and provider-neutral.
- Provider behavior is represented through profile metadata, not hardcoded logic.
- Saudi/GCC placeholders are specified as future profiles only.

Architecture constraints:
- No country hardcode in core integration contracts.
- No provider-specific status model as universal core state.
- No direct provider invocation in L2 foundation contracts.

## 5. Why Integration Contracts Are Separate From New Modules

- New modules establish internal domain foundations.
- Integrations require external boundary governance and credential safety.
- Integration foundations need explicit anti-fake and no-live-call controls.
- Therefore A-027.5 is isolated as a dedicated integration-contract planning step.
