# A-055.7 Runtime Scheduling Section Selector And Enrollment Drop Contract Report

Date: 2026-06-18

## Scope

Seventh correction slice after student enrollment selector shell:

```text
course
  -> scheduled section
  -> term
  -> enrollment
  -> drop lifecycle
```

The goal of this slice was to connect enrollment creation to the real scheduling section contract and fix the enrollment drop payload expected by the backend lifecycle service.

## Backend Result

Scheduling now exposes tenant-scoped section listing:

```text
GET /api/admin/scheduling/sections
```

Supported query shape:

```text
page
page_size
status
term_id
course_id
```

The response is paginated and returns canonical section records:

```text
id
tenant_id
course_id
term_id
section_code
instructor_id
max_capacity
status
version
```

## Frontend Result

Enrollments page now:

- loads scheduling sections through `useSections`
- shows a section selector when tenant sections exist
- derives `course_id`, `term_id`, and `section_id` from the selected section
- keeps manual fallback fields when no sections exist yet
- includes enrollment `version` in the detail drawer
- sends lifecycle-safe drop payload:

```text
expected_version
reason
metadata_json
```

Scheduling page now tolerates the backend canonical section shape while retaining compatibility with older display fields.

## Test Coverage Added

`EnrollmentsPage.test.tsx` now verifies:

- student/course fallback selector flow
- scheduling section selector flow
- section option labels include section code, course label, and term id
