# Admin / Platform Guide

## Purpose

Define pilot-oriented platform administration guidance for roles, permissions, troubleshooting, backups, rollback, and support.

## Intended Users

- Platform Admin

## What The Role Can Do

- review roles and permissions
- review tenant setup expectations
- coordinate troubleshooting
- coordinate backups and rollback planning
- coordinate support routing

## What The Role Cannot Do

- no real users
- no credentials publication
- no production-ready claim
- no provider integration enabled

## Basic Workflow

1. Review tenant and RBAC readiness.
2. Confirm support and rollback readiness.
3. Confirm backup expectations.
4. Route issues through pilot triage.

## Limitations

- no sales-ready claim
- no GCC readiness claim
- no Arabic runtime claim
- no real personal data

## Support Notes

- keep placeholders and non-runtime boundaries explicit
- escalate environment issues without changing business runtime

## Pilot Feedback Questions

- Which support gaps remain?
- Is the rollback outline sufficient?
- What admin documentation is still missing?
