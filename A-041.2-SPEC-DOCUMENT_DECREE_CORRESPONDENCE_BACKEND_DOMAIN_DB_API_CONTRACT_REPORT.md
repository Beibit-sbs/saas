# A-041.2-SPEC - Document / Decree / Correspondence Backend Domain / DB / API Contract Report

## 1. Executive Summary

A-041.2-SPEC defines the backend domain model, DB/table contract, API route contract, permission model, schema contract, service/repository contract, audit/evidence/archive model, signature-readiness model, delivery-readiness model, bridge model, and runtime acceptance criteria for the Document / Decree / Correspondence Suite selected in A-041.0-SPEC and mapped in A-041.1-SPEC. This action is docs-only, planning-only, and specification-only. No runtime implementation started. No backend changes, no frontend changes, and no Playwright changes were made.

Strategic decision: preserve canonical reuse first. The future backend wrapper is allowed only if needed at `backend/app/modules/document_decree_correspondence/`. If created in A-041.2-RUNTIME, that wrapper acts as an aggregation/readiness/evidence/audit/archive/bridge layer over existing document, decree, correspondence, template, rector-resolution, assignment, archive, audit, and committee-decision canonicals. It must not duplicate canonical workflow cores, must not execute legal approvals, must not sign documents, must not submit externally, and must not claim official delivery or legal effect.

This backend contract is complete for the future wrapper option:

- future wrapper path: `backend/app/modules/document_decree_correspondence/`
- future wrapper table count: `26` `ddc_` tables if wrapper DB is used
- future API route count: `53`
- future permission count: `50`
- future runtime module files: `8`
- permission namespace: `document_decree_correspondence.*`

The prior A-032 scoped slice was reviewed as strong reuse evidence, but it is not counted as an A-041 closed vertical and does not replace the A-041 runtime/frontend/E2E/closure chain.
