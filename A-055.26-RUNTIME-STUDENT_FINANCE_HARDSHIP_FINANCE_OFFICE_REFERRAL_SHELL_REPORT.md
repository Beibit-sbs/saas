# A-055.26 Runtime - Student Finance Hardship Finance-Office Referral Shell Report

## Scope

Add a metadata-only referral from Student Services Support hardship review to the finance-office follow-up queue:

```text
human-reviewed hardship -> finance-office referral metadata -> audit event
```

## Result

Added a guarded finance-office referral endpoint:

- Backend route:
  - `POST /api/admin/student-services/hardship/from-finance-handoff/{hardship_id}/finance-office-referral`
- Backend permission:
  - guarded by `admin.student_services.write`
- Backend behavior:
  - verifies tenant scope,
  - verifies the hardship record came from `student_finance_receivables_handoff`,
  - stores finance-office referral metadata in hardship `metadata_json`,
  - updates hardship status to `finance_office_referral_recorded`,
  - emits `hardship.finance_office_referral_recorded`.
- Frontend API:
  - `createFinanceHardshipFinanceOfficeReferral(...)`
- Frontend dashboard shell:
  - shows the finance-office referral endpoint and expected metadata fields beside each reviewer queue item.

## Safety Boundaries

The referral is metadata-only.

It does not approve aid, reject aid, cancel debt, mutate billing balances, execute payments, submit provider requests, or create a hidden score.

Explicitly preserved:

- `noAutomaticAidDecision=true`
- `noBillingBalanceMutation=true`
- `noPaymentExecution=true`
- `humanReviewRequired=true`
- `fake_metrics=false`
- `provider_live_enabled=false`
- `autonomous_decision_enabled=false`
- `hidden_score_present=false`
