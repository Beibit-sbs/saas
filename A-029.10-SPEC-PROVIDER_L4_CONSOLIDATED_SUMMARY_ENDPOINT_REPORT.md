## 6. Consolidated Endpoint Standard

A consolidated provider L4 summary endpoint must:

- **HTTP Method**: GET only (no POST/PUT/PATCH/DELETE)
- **Permission**: admin.expansion.read (consistent with individual 11 routes)
- **Tenant Scope**: tenant-safe, fail-closed for None/0/-1/invalid tenant_id
- **Read-Only**: no mutations
- **Deterministic**: same tenant input returns same response across calls
- **Non-Live Integration**: NON_LIVE_READINESS boundary
- **No Provider Calls**: reads only from existing L4 service summaries or A-029.8 route handler logic
- **No Credentials**: no credential validation, storage, or retrieval
- **No Sync**: no sync polling or state reconciliation
- **No External Submission**: no records submitted to external systems
- **No Connected Claim**: readiness remains L4_PROVIDER_READONLY, not "provider_connected"
- **No Success Claim**: no "integration_successful" or "provider_available" fields
- **No Brain/Autonomy**: no rule execution, no workflow triggers, no autonomous decisions
- **No Mutation Routes**: individual provider routes remain unchanged

### Aggregation Strategy
- Call existing A-029.7 provider L4 service summary functions directly
- Do NOT call internal HTTP routes (avoid route-to-service-to-route cycles)
- Do NOT reimplement provider logic
- Do NOT synthesize new readiness classifications
- Aggregate 11 service summary results into single consolidated response

### Response HTTP Status
- 200 OK: successful aggregation
- 401 Unauthorized: no valid JWT
- 403 Forbidden: insufficient permission or cross-tenant override attempt
- 400 Bad Request: invalid tenant_id
