# A-056.4 Runtime - Digital Twin Live Enrollments Wiring Report

## Scope

Wire the capacity what-if's `current_students` to a LIVE read from the
enrollments module (best-effort), so the twin projects from real data instead
of only caller-provided baselines — still read-only, evidence-explained,
human-gated, with an honest fallback.

## Result

- Request gains `use_live_sources: bool = False` (opt-in).
- When set, `current_students` is read from `enrollments.service.list_enrollments(tenant_id)`
  (tenant-scoped count) via a best-effort helper `_live_enrollment_count` that returns
  `None` on any failure.
- If the live read resolves: `current_students` is overridden, the evidence entry
  is tagged `mode="live"`, and `live_sources_used` includes `"enrollments"`.
- If it fails (no source / exception): honest fallback to the caller value,
  `mode="caller_provided"`, `live_sources_used=[]` — **no fabrication**.
- Cross-module coupling is service-level only (calls the enrollments public
  service, not its models), wrapped in try/except — consistent with the
  recovery duplication protocol.

## Safety / Honesty

- No fabricated values: live or caller-provided, always tagged which.
- `human_review_required=true`, `fake_metrics=false`, no autonomous action.
- Read-only: persists nothing, executes nothing. Viewer still denied (403).

## Contract

- No new route/permission (route count remains 3, permission 3). Additive
  request field + response field (`live_sources_used`) + evidence `mode`.
