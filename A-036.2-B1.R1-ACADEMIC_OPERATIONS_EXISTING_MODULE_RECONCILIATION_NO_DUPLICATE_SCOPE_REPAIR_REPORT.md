## 4. Reconciliation Method

R1 used the following rules:

1. If a desired module already exists as a canonical tracker module with equivalent scope, classify it `EXISTING_CANONICAL_MODULE`.
2. If a desired module is not canonical by the exact desired name but is already materially represented by one or more adjacent canonical modules or workflows, classify it `EXISTING_ADJACENT_MODULE`.
3. If a desired module would mainly duplicate an already-existing vertical and should be implemented only as a read-only or metadata bridge, classify it `BRIDGE_TO_EXISTING_VERTICAL`.
4. If no canonical or adjacent canonical sufficiently covers the desired scope, classify it `NEW_TRUE_MODULE`.
5. Only classify `DEFERRED_FUTURE_VERTICAL` when the module belongs to a different product vertical and should not stay inside A-036 at all.
