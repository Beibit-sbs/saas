# A-055.27 Runtime - Student Finance Hardship Finance-Office Referral Queue Visibility Report

## Scope

Surface the finance-office referral queue (already exposed by the backend in A-055.26) in the Student Services Support dashboard, read-only:

```text
recorded finance-office referral -> dashboard referral queue visibility -> no financial action
```

## Result

Added a dedicated read-only dashboard panel:

- Frontend component:
  - `FinanceHardshipFinanceOfficeReferralQueuePanel`
- Data source:
  - existing hook `useFinanceHardshipFinanceOfficeReferralQueue()`
  - existing endpoint `GET /api/admin/student-services/hardship/from-finance-handoff/finance-office-referral-queue`
- Panel shows per referral item:
  - source hardship id, request id, receivables metadata id,
  - referral target, referral priority, referral reason,
  - target module and recording reviewer (referred_by_user_id),
  - explicit safety flags.
- Wired into the `dashboard` route beside the reviewer queue panel.
- Dashboard seed extended with a `finance_office_referral_recorded` referral item so the panel renders deterministic metadata.

## Safety Boundaries

The panel is read-only visibility of metadata already recorded.

It does not approve aid, reject aid, cancel debt, mutate billing balances, execute payments, or submit provider requests.

Explicitly preserved on every item:

- `noAutomaticAidDecision=true`
- `noBillingBalanceMutation=true`
- `noPaymentExecution=true`
- `humanReviewRequired=true`
