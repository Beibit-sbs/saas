## L4 Service Summary Contract

Each L4 visibility summary provides 30 required fields:

### Core Metadata (5 fields)
- `tenant_id`: Numeric tenant identifier (fail-closed on validation)
- `module`: Module name constant (e.g., "staff_recruitment")
- `uce_id`: Universal Contract Enumeration identifier
- `visibility_level`: "L4" (fixed)
- `source_maturity_level`: "L3" (shows base contract source)
- `visibility_type`: "READ_ONLY_SERVICE_SUMMARY" (fixed)

### Readiness Summary (4 fields)
- `readiness_summary.status`: Classification status from L3 (e.g., "READY_FOR_REVIEW", "BLOCKED_MISSING_EVIDENCE")
- `readiness_summary.evidence_completeness`: Percentage (0-100) from L3
- `readiness_summary.recommended_next_step`: Guidance text from L3
- `readiness_summary.ready_for_human_review`: Boolean derived from status

### Risk & Evidence Summaries (8 fields)
- `risk_summary.risk_band`: Risk category from L3 classification
- `evidence_summary.required_evidence_count`: Count of required evidence items
- `evidence_summary.present_evidence_count`: Count of present evidence items
- `evidence_summary.missing_evidence_count`: Count of missing evidence items
- `evidence_summary.required_evidence`: List of required evidence item names
- `evidence_summary.present_evidence`: List of present evidence item names
- `missing_evidence_summary.count`: Duplicate count for convenience
- `missing_evidence_summary.items`: List of missing evidence item names

### Action Governance (2 fields)
- `allowed_actions`: List of safe read-only operations (VIEW_L4_VISIBILITY_SUMMARY + L3 allowed_actions)
- `forbidden_actions`: List of unsafe operations from L3 contract (always enforced read-only)

### Safety Flags (14 fields)
- `tenant_scoped`: True (all outputs scoped by tenant)
- `read_only`: True (no state mutations allowed)
- `no_mutation`: True (explicit mutation prohibition)
- `no_provider_call`: True (no external provider integration)
- `no_external_submission`: True (no external systems)
- `no_brain_execution`: True (no AI/ML model execution)
- `no_autonomous_execution`: True (no autonomous workflows)
- `no_workflow_execution`: True (no workflow triggers)
- `no_decision_execution`: True (no decision engine calls)
- `no_fake_kpi`: True (no synthetic/fake metrics)
- `no_synthetic_score`: True (no generated scores)
- `no_synthetic_dashboard`: True (no generated visualizations)
- `no_l5_claim`: True (no L5 visibility claims)
- `no_l6_claim`: True (no L6 visibility claims)

### Governance & Contract Preservation (2 fields)
- `l3_contract_preserved`: True (L3 contract fully preserved)
- `api_route_deferred_to`: "A-028.10" (API route implementation deferred)

## Implementation Details

### Function Signatures

All L4 entry points follow standard signature:
```python
def get_{module}_l4_visibility_summary(
    tenant_id: int, 
    present_evidence: list[str] | set[str] | dict | None = None
) -> dict:
    """L4 read-only visibility summary for {module} ({uce_id})."""
```

### Tenant Validation

Two patterns used (per module:tenant_validator mapping):

**Pattern A** (4 modules: staff_recruitment, staff_onboarding, employee_records, leave_management):
```python
tenant_id = _validate_tenant_id_l3(tenant_id)
```

**Pattern B** (6 modules: dormitory_management, partnership_registry, mou_lifecycle, scholarship_committee_workflow, student_appeals_workflow, consent_management_policy):
```python
tenant_id = validate_tenant_id(tenant_id)
```

Both validate tenant_id and fail-closed on None/0/negative values.

### Evidence Parameter Handling

Two parameter conventions identified during implementation:

**Convention A** (6 modules): L3 function accepts `present_evidence` parameter
- staff_recruitment, staff_onboarding, employee_records, leave_management, scholarship_committee_workflow, student_appeals_workflow

**Convention B** (4 modules): L3 function accepts `evidence` parameter (dict only)
- dormitory_management, partnership_registry, mou_lifecycle, consent_management_policy

L4 wrappers normalize input and pass correct parameter name to underlying L3 function.

### Output Structure

All L4 outputs are flat dictionaries with nested organization:
- Readiness summaries nested under `readiness_summary` key
- Risk metrics nested under `risk_summary` key
- Evidence lists nested under `evidence_summary` and `missing_evidence_summary` keys
- All safety flags at root level for easy access in API responses
