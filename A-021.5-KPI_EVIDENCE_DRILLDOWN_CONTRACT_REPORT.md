# A-021.5 - KPI EVIDENCE DRILLDOWN CONTRACT REPORT

## 1. Executive Summary

A-021.5 delivers a tenant-scoped, read-only KPI Evidence Drilldown Contract in the rector/ministry governance dashboard. The section explains why each KPI/risk/alert group is shown, which source metric keys support it, which source domains it comes from, what evidence summary exists, whether human review is required, and whether evidence is unavailable/incomplete. The implementation is reuse-first and frontend-only over existing `data.cards`; no backend endpoint, migration, destructive automation, or external ministry submission was introduced.

## 6. Drilldown Model

- `dataQualityNote`
- `readonly` (`true`)
- `tenantScoped` (`true`)
- `evidenceSources` (line-item source entries)

## 7. Deterministic Derivation Rules

From existing tenant KPI snapshot evidence only:
- If domain has no available metric cards -> `riskLevel=unavailable`.
- Else if any critical key > 0 -> `riskLevel=critical`.
- Else if any high key > 0 -> `riskLevel=high`.
- Else if medium/review keys > 0 -> `riskLevel=medium`.
- Else -> `riskLevel=low`.

Human review flag:
- `reviewRequired=true` when review/high/critical signals are positive.
- Otherwise `reviewRequired=false`.

Evidence summary:
- Built from positive available metric entries.
- If evidence exists but no elevated values: explicit non-elevated summary.
- If no evidence exists: explicit unavailable summary.
