- no cross-tenant data exposure

2. Schema / response contract
- Pydantic response schema
- deterministic response shape
- explicit readiness/classification fields
- no fake or speculative fields

3. Permission / RBAC / ABAC
- `permission_dependency(...)` or repo-equivalent guard required
- no unauthenticated access
- role/scope documented
- tenant ownership boundary enforced

4. Tenant safety
- tenant from authenticated context (`get_current_tenant` or repo-equivalent)
- fail-closed if tenant missing or invalid
- no default tenant fallback
- response confirms tenant scope or tenant-bound resource isolation

5. Tests
- route import / app registration validation
- response schema validation
- permission denial test
- tenant fail-closed test
- no cross-tenant leakage test
- anti-inflation test
- read-only / no-mutation test

6. Frontend/admin visibility
- frontend is optional, not automatic
- backend/admin API is sufficient for this batch
- no broad UI expansion in A-026.5-RUNTIME unless separately re-approved

7. Anti-inflation
- no Brain signal claim
- no KPI lineage claim unless explicitly implemented
- no autonomous action
- no solver/AI-provider call
- no L5/L6 claim
- no fake operational data
