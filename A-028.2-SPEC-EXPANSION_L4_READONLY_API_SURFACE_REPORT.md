## 8. Read-Only API Route Standard

### A-028.2 Read-Only Admin API Route Standard

Route requirements:
- HTTP method: `GET` only
- tenant-safe and fail-closed
- guarded with `permission_dependency(...)`
- authentication derived through `get_actor`
- tenant resolved through `get_current_tenant`
- no DB mutation
- no workflow execution
- no approval/rejection/assignment/closure execution
- no external provider call
- no Brain/autonomy execution
- no fake KPI / synthetic dashboard value
- response derived from A-028.1 L4 service summary functions
- response must preserve `read_only=True`, `tenant_scoped=True`, and `no_mutation=True`
- `forbidden_actions` must remain present in every response

Route design options reviewed:
- Option A: individual endpoints
- Option B: consolidated endpoint with `modules=...`
- Option C: hybrid consolidated + optional individual endpoints

Recommended option:
- Option A, implemented on one dedicated router file

Reason:
- existing admin route conventions favor explicit resource endpoints
- avoids module query parsing and mixed-permission ambiguity
- simplifies per-endpoint documentation and testing
- keeps first runtime batch narrow and easy to audit

Common response fields:
- `tenant_id`
- `module`
- `uce_id`
- `visibility_level`
- `source_maturity_level`
- `readiness_summary`
- `risk_summary`
- `evidence_summary`
- `missing_evidence_summary`
- `human_review_queue_summary`
- `read_only`
- `tenant_scoped`
- `no_mutation`
- `safety_flags`
- `forbidden_actions`

Permission strategy:
- preferred route guard: `permission_dependency("admin.expansion.read")`
- if runtime cannot introduce a dedicated permission cleanly, it must reuse the nearest existing read permission consistently across the selected batch and document that choice explicitly
- this spec does not implement permission registration

Tenant strategy:
- do not expose a path or query `tenant_id` override in the first runtime batch
- derive tenant from authenticated token via `get_current_tenant`
- permit `X-Tenant-ID` only as a validation hint consistent with existing fail-closed tenant rules
