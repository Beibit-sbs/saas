# A-056.3 Runtime - Digital Twin Capacity What-If Simulation Report

## Scope

First REAL Digital Twin computation node: a deterministic, read-only capacity
what-if. The twin moves from declaring a contract (A-056.1/.2) to actually
projecting capacity risk — without fabricating values, without autonomy.

## Result

- Backend route: `POST /api/admin/digital-twin/simulate/capacity` (read-only
  computation; persists nothing, executes nothing).
- Permission: new `digital_twin.simulate.run` (route count 2→3, permission 2→3 module-local).
- Service `simulate_capacity`: deterministic arithmetic on caller-provided baselines:
  - `projected_students = round(current_students × (1 + intake_growth_percent/100))`
  - `classroom_utilization = projected / classroom_capacity` (None when capacity unknown)
  - `dormitory_pressure = round(projected × housing_demand_ratio) / dormitory_capacity`
  - `risks` flagged when a ratio > 1.0.
- Evidence lineage: each input tagged to its source module
  (current_students→enrollments, classroom_capacity→scheduling, dormitory_capacity→dormitory_management).
- Frontend: read-only "Capacity what-if (deterministic)" section on /console/digital-twin.

## Honesty / Safety (no fake metrics, no autonomy)

- No value is fabricated: the math is deterministic on real inputs. Missing
  inputs (capacity=0) yield `incomplete_data=true` and a `null` ratio — never a guess.
- `human_review_required=true`, `fake_metrics=false`, `provider_live_enabled=false`.
- Output is a human-review readout; it proposes nothing and executes nothing.
- RBAC: a viewer without `digital_twin.simulate.run` is denied (403).
