## 1. Scope

Extend the Brain Core `academic_integrity` scenario family with a new **case resolution** sub-scenario: `academic_integrity_case_resolution`. This enables the platform to automatically route integrity events to the correct review workflow, classify risk/priority, and enforce a mandatory human-in-the-loop gate before any high- or critical-severity case action is taken.

**Hard constraint:** No automatic sanctions. No grade change, no exam invalidation, no thesis rejection, no ethics outcome written automatically. All consequential actions require human approval.

## 3. Brain Core Deterministic Model

### 3.1 Supported Event Types

| Event Type | Description |
|------------|-------------|
| `academic_integrity.case.opened` | New integrity case created |
| `academic_integrity.case.evidence_requested` | Evidence gathering stage |
| `academic_integrity.case.review_required` | Escalated to reviewer |
| `academic_integrity.case.resolved` | Case closed with outcome |
| `academic_integrity.case.dismissed` | Case dismissed |
| `integrity.resolution.workflow_needed` | Workflow trigger |

### 3.2 Risk Classification

| Priority | Condition |
|----------|-----------|
| CRITICAL | Explicit `risk_level="critical"` **OR** `days_open >= 30` |
| HIGH | Explicit `risk_level="high"` **OR** `days_open >= 14` **OR** source_decision_type in `{academic_integrity_review, exam_integrity_review, research_ethics_review}` (when no explicit risk_level) |
| MEDIUM | Explicit `risk_level="medium"` **OR** `evidence_missing=True` (when no explicit risk_level) |
| LOW | Default |

**Critical design decision:** Explicit `risk_level` always takes priority over contextual signals. This prevents a medium/low explicit signal from being upgraded due to source_decision_type alone.

### 3.3 Decision Actions by Priority

| Path | Actions | requires_approval |
|------|---------|-------------------|
| CRITICAL | open_review_case, notify_committee, escalate_overdue_case, mark_ready_for_human_decision | **True** |
| HIGH | open_review_case, assign_reviewer, notify_committee, mark_ready_for_human_decision | **True** |
| MEDIUM | open_review_case, request_evidence, assign_reviewer | False |
| LOW | open_review_case | False |

### 3.4 Safety Guarantees

- **No punitive actions** (`suspend_student`, `revoke_grade`, `invalidate_exam`, `reject_thesis`, `ban_account`) are present in any action_map entry.
- **Human-in-the-loop mandatory** for HIGH and CRITICAL (`requires_approval=True`); `mark_ready_for_human_decision` action is emitted for both.
- **Fail-closed on missing tenant**: signals with `tenant_id=0` or `tenant_id<0` return `status="failed"`, `reason="invalid_tenant"`.
- **Fail-closed on missing case reference**: signals with no `case_id`, `source_decision_id`, or `source_entity_id` return `status="failed"`, `reason="missing_case_reference"`.
- **Deduplication**: Same signal processed twice returns `status="deduplicated"` on the second call.
- **Tenant isolation**: Signals from different tenants processed independently.
